What is Networking?

Networking is the practice of connecting two or more computing devices so they can exchange data, share resources, and communicate. A network is defined not by the number of devices but by the ability to transmit and receive information between endpoints using agreed-upon standards and protocols.

Key idea — memorize
Networking enables resource sharing (files, printers, compute, storage) and communication (email, voice, video, web) between endpoints regardless of location — locally via a LAN or across sites via a WAN. The Internet is a network of networks; not every network is the Internet.

What a network needs — 5 building blocks

  • Endpoints / hosts — PCs, servers, phones, IoT; originate or consume traffic.
  • Transmission media — copper (UTP/STP), fiber (single-mode/multimode), or RF (wireless).
  • Intermediary devices — switches, routers, firewalls, APs that move/secure data.
  • Protocols — rules for formatting, addressing, and delivering (TCP/IP, Ethernet, 802.11).
  • Addressing — MAC (L2) and IP (L3) identifiers that let packets find the right destination.
What networking must solve — connecting heterogeneous devices; addressing & naming; path determination; reliability & error recovery; security; management & monitoring. All solved together via layering (OSI model).

Network Types

Networks are classified by geographic scope (PAN → LAN → MAN → WAN), by transmission medium (WLAN, SAN), or by who controls connectivity (VPN). A single enterprise uses almost all at once.

Special-purpose types — at a glance

WLANSame scope as LAN but RF (802.11) — AP/WLC managed; shared medium, more interference and security exposure vs wired.
SANDedicated block-level storage network (Fibre Channel / iSCSI) — separate from user/data LAN; optimized for throughput & low latency.
VPNLogical encrypted tunnel over existing network (site-to-site IPsec, remote SSL/IPsec) — gives confidentiality, integrity, and private addressing overlay without owning physical links.

Side-by-side comparison

FactorClient-ServerPeer-to-Peer
ControlCentralized on serverDistributed / equal peers
SecurityCentral auth, audit, patchingWeak / none by default
ScalabilityCluster + load balancerOrganic; each new peer adds capacity & load
SPOF riskServer — mitigate with HA clusterNo central SPOF, but peers may be offline
Enterprise verdictDefault choice for manageabilityRestricted to specific use cases (updates, caching, blockchain)
ENCOR twist: BGP/OSPF "peers" are equal control-plane partners — the word "peer" there means adjacency relationship, not application model. That distinction between data-plane C/S and control-plane peering is a recurring theme.

Network Components & the Three Planes

Devices by layer

DeviceLayerCore Job
Hub (legacy)L1Repeats signal to all ports — one collision domain; avoid.
SwitchL2 / L3MAC forwarding (CAM), VLANs, microsegmentation; L3 switches route VLANs (FIB).
RouterL3Path selection by IP (RIB/CEF), interconnects networks, NAT/filtering.
Wireless APL2Bridges 802.11 RF frames onto the wired LAN.
FirewallL3–L7Stateful session tracking, policy enforcement, NAT/VPN/IPS.
Load balancerL4–L7Distributes flows across a server farm; health checks.
WLCMgmt/CtrlCentralizes AP config, RF management, roaming.

The three planes — key ENCOR concept

Data PlaneUser packet forwarding path — runs on ASICs/TCAM; measured in pps/fib. Example: switching fabric, CAM table, FIB.
Control PlaneDecides how to forward — builds routing/forwarding tables. Example: OSPF/EIGRP/BGP, ARP/ND, STP.
Management PlaneHow we administer the box — SSH, SNMP, syslog, NTP, NetFlow, RESTCONF/NETCONF, SDN controller.

Supporting design rules

  • Hierarchy — three-tier modules give consistent behavior & isolation.

One-Minute Summary & Self-Test

Networking Basics in 60 seconds

Network = 2+ devices exchanging data via agreed standards — size is irrelevant.
A network needs: endpoints, media, intermediary devices, protocols, addressing.

Scope (smallest → largest):  PAN (~10 m) → LAN (building) → MAN (city) → WAN (global/carrier).
Special: WLAN = RF-based LAN (802.11); SAN = dedicated block-level storage net (FC/iSCSI);
         VPN = encrypted logical tunnel over another network (IPsec/SSL).

Models: Client-Server (centralized server, enterprise default) vs Peer-to-Peer (equal peers, no SPOF but weak security).
BGP/OSPF "peers" = control-plane adjacency — different from application-layer P2P.

Devices:  Hub = L1 | Switch = L2/L3 (CAM/FIB) | Router = L3 (RIB) | AP = L2 (RF bridge)
          Firewall = L3-L7 (stateful) | LB = L4-L7 | WLC = mgmt/control

Three planes:
  Data    = packet forwarding (ASIC/TCAM/CAM/FIB)
  Control = routing/forwarding table build (OSPF, STP, ARP)
  Mgmt    = admin access (SSH, SNMP, syslog, NetFlow, RESTCONF)

Architecture: Core (fast, no policy) → Distribution (policy/QoS/ACL/HSRP) → Access (ports/VLANs/PoE).
Collapsed core = core+distribution merged (small site).

Design pillars: Fault Tolerance | Scalability | QoS | Security | Manageability.
Anti-patterns: policy in core, single gateway in HA pair, flat L2 campus, no management VLAN separation.
