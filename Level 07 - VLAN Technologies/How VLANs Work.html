🧱 VLAN Basics — Layer 2 broadcast domains

A VLAN (Virtual Local Area Network) logically divides a Layer 2 switched network into multiple broadcast domains. Devices in the same VLAN talk at Layer 2; devices in different VLANs need Layer 3 routing.

Key idea: A VLAN is a Layer 2 broadcast boundary. Different VLANs cannot talk at Layer 2 — they require Layer 3 routing to communicate.

How a frame is classified

1. Access port receives an untagged frame
2. Switch associates it with the port's access VLAN
3. Forwarded within that VLAN's broadcast domain
4. Across trunks → 802.1Q tag identifies the VLAN
Trap: Access-port host traffic is normally untagged; trunks normally tag (except the native VLAN). Do not answer "access ports tag frames" or "trunks are untagged."

🎙️ Voice VLAN — phone + PC on one port

A dedicated VLAN carries IP phone / VoIP traffic separately from data. A phone and a PC can share one physical switch port: PC → data VLAN (untagged), phone → voice VLAN (tagged).

Key point: switchport voice vlan 20 does not turn the port into a trunk — it remains an access port with an extra voice association.

🔒 Private VLAN (PVLAN) — L2 isolation in one subnet

PVLANs subdivide a primary VLAN into smaller forwarding domains so hosts can share one IP subnet yet be isolated at Layer 2 — without one VLAN/subnet per host.

🔌 Access Port — one data VLAN

An access port belongs to one access VLAN and normally connects end devices (PC, printer, camera). Endpoint traffic is normally untagged; the switch associates it with the port's access VLAN.

🔀 Trunk Port — many VLANs on one link

A trunk carries multiple VLANs over one physical link using 802.1Q tagging. The native VLAN is the exception — it normally flows untagged.

Allowed VLAN list explorer

These VLANs are configured on the trunk. Toggle allowed on/off to see what crosses.

{{ v.id }}
Reminder: removing a VLAN from the allowed list does not delete it from the switch — it only stops it crossing that trunk. Check with show interfaces trunk.

Trunk configuration

interface GigabitEthernet0/24
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
 switchport trunk native vlan 999
 switchport nonegotiate     # disables DTP, NOT trunking

Native VLAN mismatch

The native VLAN must be consistent on both ends. A mismatch misclassifies untagged traffic — it does not normally break correctly tagged VLAN traffic.

Security: native VLAN behavior is central to double-tagging VLAN hopping. Restrict allowed VLANs, use a dedicated native VLAN, keep both ends in sync.

🏷️ Native VLAN — the untagged trunk VLAN

On an 802.1Q trunk, the native VLAN is the VLAN whose frames normally travel untagged. Cisco's default is commonly VLAN 1, but it can be changed.

Tagged vs untagged

VLAN 10
→ tagged (802.1Q)
VLAN 20
→ tagged (802.1Q)
NATIVE 999
→ untagged

Match (correct)

SW A: 999 · SW B: 999
untagged = VLAN 999 both ends

Mismatch (broken)

SW A: 999 · SW B: 100
untagged classified differently → leaks/traps

Router-on-a-stick native

interface GigabitEthernet0/0.999
 encapsulation dot1Q 999 native   # untagged frames → VLAN 999
 ip address 10.1.99.1 255.255.255.0
Hardening: vlan dot1q tag native can make even the native VLAN tagged where supported — extra protection against double-tagging.

📦 802.1Q — the IEEE trunk tagging standard

IEEE 802.1Q defines VLAN tagging. A 4-byte tag (TPID + TCI) is inserted between Source MAC and EtherType. Tagged frames are +4 bytes larger (1518 → 1522).

🥞 QinQ (802.1ad) — VLAN stacking

QinQ adds an outer S-Tag (provider/service) to an already-C-Tag (customer) frame, letting a provider transport many customers' VLANs without renumbering. Overhead vs untagged = +8 bytes.

How customers stay separate

Customer A: C-VLAN 10 → S-VLAN 100
Customer B: C-VLAN 10 → S-VLAN 200
Customer C: C-VLAN 10 → S-VLAN 300

Same C-VLAN numbers stay distinct because the S-VLAN context separates them.

Frame flow through provider

1. Customer sends [C-Tag 10]
2. PE adds [S-Tag 100]
3. Provider transports [S100][C10]
4. Destination PE removes S-Tag
5. Customer gets [C-Tag 10] back
Trap: QinQ is a legitimate service — it is not the same as a double-tagging VLAN-hopping attack, even though both use two tags. Cisco config: switchport mode dot1q-tunnel.

🛣️ Inter-VLAN Routing — L3 between VLANs

Different VLANs are separate L2 broadcast domains (and normally separate IP subnets) — crossing between them needs a Layer 3 gateway. Three implementation models:

Distinction: an SVI is just a logical L3 interface for a VLAN; ip routing is what enables the switch to route. Hardware ASIC forwarding = fast & scalable.

Routed Access

🥢 Router-on-a-Stick — one trunk, many subinterfaces

ROAS uses one physical router interface on an 802.1Q trunk, with one subinterface per VLAN acting as that VLAN's default gateway.

Gateway mapping explorer

VLAN 10

Gi0/0.10 → 10.1.10.1

VLAN 20

Gi0/0.20 → 10.1.20.1

VLAN 30

Gi0/0.30 → 10.1.30.1

Subinterface number doesn't set the VLAN — encapsulation dot1Q <id> does. Gi0/0.100 with encapsulation dot1Q 10 is valid.

Full config

interface GigabitEthernet0/0
 no ip address
 no shutdown

interface GigabitEthernet0/0.10
 encapsulation dot1Q 10
 ip address 10.1.10.1 255.255.255.0

interface GigabitEthernet0/0.20
 encapsulation dot1Q 20
 ip address 10.1.20.1 255.255.255.0

interface GigabitEthernet0/0.999
 encapsulation dot1Q 999 native   # native VLAN
 ip address 10.1.99.1 255.255.255.0

! switch port
interface GigabitEthernet0/24
 switchport mode trunk
 switchport trunk native vlan 999
 switchport trunk allowed vlan 10,20,999

How it routes (VLAN 20 → VLAN 10)

1. Host A sees remote dest → sends to gateway 10.1.20.1
2. Switch trunks the frame tagged VLAN 20
3. Router receives on Gi0/0.20
4. L3 lookup → out Gi0/0.10
5. Router rebuilds frame tagged VLAN 10
6. Switch delivers to VLAN 10
Trap: The router routes (L3), it doesn't bridge VLANs. Physical interface normally has no IP. `native` keyword is required for the untagged VLAN — a normal dot1Q subinterface does not auto-handle untagged traffic.
