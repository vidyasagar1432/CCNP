DHCP Relay

Put ip helper-address on the client-facing L3 interface (NOT server-facing). The relay sets the giaddr field so the server knows the client's subnet.

interface Vlan10
 ip helper-address 10.0.0.5     <-- client-facing
Note: ip helper-address is not DHCP-only — it also forwards DNS (53), TFTP (69), NetBIOS (137/138) UDP broadcasts. It does NOT create a route, and multiple helpers ≠ DHCP failover.

DHCP Snooping

A Layer 2 security feature. Interfaces are untrusted by default; trust only toward the real DHCP server. OFFER/ACK/NAK are dropped on untrusted ports (blocks rogue servers); rate-limit mitigates starvation.

1 untrusted by default
2 trust toward server
3 build binding DB
4 feed DAI + IP Source Guard
Relationship: DHCP Snooping → binding database (MAC+IP+VLAN+intf+lease) → DAI (validates ARP) and IP Source Guard (restricts source traffic).

🕐 NTP — time sync & stratum

Network Time Protocol synchronizes clocks over UDP 123. Key concept = stratum (distance from the reference clock).

Operating modes

CommandMeaning

📁 FTP vs TFTP — file transfer

FTP is a full transport-connection file protocol; TFTP is a tiny UDP file pull/push used for device images.

FTP mode explorer

{{ m.name }}
{{ m.desc }}
{{ ftpVerdict.text }}
ModeData initiated byServer data source port
ActiveServer → ClientTCP 20
PassiveClient → Serverdynamic / high port

Memory: Active = Server → Client for data · Passive = Client → Server for data. Control is always TCP 21.

Security: FTP sends credentials and data in cleartext. FTPS = FTP + TLS. SFTP = SSH-based (a different protocol, NOT "secure FTP").

TFTP — lock-step over UDP

MessagePurpose
RRQread request (client reads)
WRQwrite request (client writes)
DATAnumbered data blocks
ACKacknowledges each DATA

UDP 69 is only the initial request; the transfer itself uses dynamic UDP ports. Classic block = 512 bytes (negotiable: blksize/tsize/windowsize). Final DATA smaller than block size = EOF; exact multiple → a zero-length DATA marks EOF.

TFTP vs FTP: connectionless, no auth, no encryption, no directory listing. Used for IOS image/config transfer; Option 150 → TFTP server for Cisco IP phones.

🔐 SSH & Telnet — remote CLI

SSH = TCP 22, encrypted remote management (v2 preferred). Telnet = TCP 23, no encryption — cleartext credentials + session.

SSH connection stages

1 TCP handshake
2 version exchange
3 key exchange / negotiation
4 server auth (host key)
5 user auth
6 encrypted session

Cisco SSH config

hostname R1
ip domain-name ccnp.example
username admin privilege 15 secret AdminPass123
crypto key generate rsa modulus 2048   <-- hostname + domain-name first
ip ssh version 2
ip ssh time-out 60
ip ssh authentication-retries 3
line vty 0 15
 login local
 transport input ssh                  <-- allow SSH, block Telnet
Traps: hostname + ip domain-name are required before generating RSA keys. transport input ssh controls incoming VTY access. SCP = file copy over SSH (22); SFTP = SSH-based (platform dependent). ACLs restrict who connects but do NOT make Telnet secure.

📞 SIP + RTP — voice & media

SIP is the signaling that sets up/tears down calls (5060, or 5061 for TLS). RTP carries the actual media. RTCP (RTP port + 1) reports quality.

SIP methods

MethodPurpose
INVITEestablish session
ACKconfirm INVITE
BYEend session
REGISTERregister with registrar
OPTIONScapability query
CANCELabort pending setup

SIP call flow

UAC --INVITE--> UAS
UAC <--100/180-- UAS  (trying / ringing)
UAC <--200------ UAS  (OK with SDP)
UAC --ACK------> UAC
^^^^^^^^ RTP media flows DIRECTLY between endpoints ^^^^^^^^
UAC --BYE------> UAS
UAC <--200------
NAT trap: NAT breaks media (RTP), not signaling → symptom is one-way audio. A NAT ALG can incorrectly rewrite SDP.
