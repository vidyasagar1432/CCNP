What is BGP?

BGP (Border Gateway Protocol) is the path-vector routing protocol of the internet. It exchanges reachability + path attributes between autonomous systems (ASes) over reliable TCP sessions — not metrics like an IGP. BGP's job isn't to find the fastest path; it's to let each AS choose paths according to policy.

Transport facts — memorize
TCP port 179 (reliable — no retransmit logic to build). Sessions use the update-source IP. BGP is incremental: full table once, then only updates — no periodic re-advertisements, no flooding.
What BGP carries
Prefixes plus path attributes: AS_PATH (loop prevention), local-pref, MED, communities, origin. The IGP (OSPF/EIGRP) can't carry these — that is exactly why iBGP exists.

The Best-Path Algorithm

One best path per prefix. The algorithm runs in strict order — the first step where the paths differ decides, and everything after never runs.

The 9-step ladder

#CriterionWinner
1Weight (Cisco proprietary)higher
2Local Preferencehigher
3Locally originatednetwork/aggregate/redistributed
4AS_PATHshorter
5Origini < e < ?

Memory mantra: Weight > Local Pref > AS_PATH > MED — the exam's four tunables in order. Steps 7–9 are the tail the exam rarely reaches.

AS_PATH

Well-known mandatory. Two jobs: loop prevention and best-path step 4 (shorter wins).

Forms and rules

TypeMeaningExample
AS_SEQUENCEordered list traversed65010 65020 65030
AS_SETunordered set (aggregation){65010, 65020}
  • Every eBGP advertisement prepends its own AS; iBGP never modifies AS_PATH.
  • Own AS anywhere in an inbound path → route rejected (it looped already).
  • AS_SET only appears from aggregate-address … as-set.

Regex cheat-sheet

PatternMeaning
^ / $anchor start / end
.any single char
_separator (space/brace)
* / +zero+ / one+
  • ^65001$ = exactly one AS
  • ^65001_ = starts with 65001
  • _65001_ = contains 65001
  • ^$ = empty path = locally originated

As-path prepend — steering inbound traffic

route-map PREPEND permit 10

 set as-path prepend 65001 65001 65001

router bgp 65001
 neighbor 192.0.2.2 route-map PREPEND out
Exam trap: only prepend your own AS number. Prepending a neighbor's AS can break its loop-detection logic and cause flapping — the classic mistake.

Local Preference

Well-known discretionary. Tells your ENTIRE AS which outbound eBGP path to prefer. Higher wins, step 2.

Properties

FactValue
Default100
Set whereinbound from eBGP (neighbor … in)
PropagatesiBGP only — external routers never see it
Best pathstep 2, higher wins
Joboutbound traffic selection (which exit your AS takes)
Exam trap: local-pref is set where eBGP routes arrive (neighbor … route-map in), then rides iBGP so every router in the AS makes the same exit choice. Apply a route-map on out and your neighbors ignore it.

MED

Optional non-transitive. Tells a NEIGHBOR AS which of your exit points to use for INBOUND traffic. Lower wins, step 6.

Properties + the direction trap

FactValue
Typeoptional non-transitive
Default0 (missing = 0 — can win by accident)
Winslower (step 6)
Comparedsame neighbor AS only (unless always-compare-med)
Travelcrosses iBGP, stripped at a third AS
AttributeSet on / judged byWhich traffic
Local Prefset inbound · judged by memy outbound exit
MEDset outbound · judged by upstreammy inbound entry
The direction trap: MED is set outbound (neighbor … route-map out) but judged inbound by the upstream AS that receives it. Setting a route-map "in" sets MED on routes arriving at you — usually wrong. 
! Two links to the upstream: prefer link A for inbound traffic
route-map SETMED permit 10
 match ip address prefix-list PRIMARY-LINK
 set metric 50                  ! lower = more preferred by upstream

router bgp 65001
 neighbor 192.0.2.2 route-map SETMED out   ! link A
 neighbor 192.0.2.3 route-map SETMED2 out  ! link B (metric 200)
Same-AS rule: MED from AS 100 and MED from AS 200 are not comparable — both count as 0 unless bgp always-compare-med is configured.

Communities

Optional TRANSITIVE tags — the upstream applies the policy, not the sender. The one attribute that crosses ASes for you.

The four well-known communities

CommunityValueAction it triggers
NO_EXPORT0xFFFFFF01don't advertise outside the local AS
NO_ADVERTISE0xFFFFFF02don't advertise to any peer
LOCAL_AS0xFFFFFF03don't leave the confederation sub-AS
INTERNET0x00000000advertise anywhere (default)
Classic trap: NO_EXPORT still flows inside your AS (kept for iBGP peers); NO_ADVERTISE dies at this router entirely (not even iBGP). Mixing them up changes the whole reachability picture.

Set, send, match

route-map COMM permit 10
 match ip address prefix-list MKT
 set community 65001:100

router bgp 65001
 neighbor 192.0.2.2 route-map COMM out
 neighbor 192.0.2.2 send-community        ! REQUIRED — else stripped

! Receiving side
ip community-list standard 10 permit 65001:100
route-map APPLY permit 10
 match community 10
 set local-preference 200
router bgp 65001
 neighbor 192.0.2.2 route-map APPLY in
Exam trap: without send-community, communities silently vanish at the outbound edge — the number-one "why is my policy doing nothing" on the exam. Standard lists match exactly; expanded lists use regex.

Scaling iBGP

iBGP split horizon demands a full mesh. Route reflectors break it with hub-and-spoke; confederations slice the AS into sub-ASes.

Session count — the reason reflectors exist

Full mesh{{ fullMesh }} sessions ( n(n-1)/2 )
With one route reflector{{ rrSessions }} sessions ( clients peer only with the RR )
Reduction{{ meshReduction }}%
n(n-1)/2 collapses to n-1 — linear instead of quadratic. That is the entire point of a route reflector.

Confederation

Split the AS into sub-ASes that peer eBGP-style while presenting one public AS outside.

router bgp 64512
 bgp confederation identifier 65001
 bgp confederation peers 64513 64514
 neighbor 10.0.0.2 remote-as 64513
SessionADBehavior
iBGP within sub-AS200iBGP rules
Confed eBGP200eBGP-ish, attributes kept
Real eBGP20normal eBGP
Exam trap: confed eBGP sessions use AD 200, not 20 — and local-pref, MED and next-hop survive sub-AS boundaries (unlike real eBGP). The confed AS_PATH is stripped before leaving to the outside world.

Policy Tools

The toolkit: aggregation, prefix-lists, route-maps, PBR. The exam's fill-in-the-blank section.

Aggregation

MethodCommandCondition
Staticnetwork X mask Yprefix must exist in the BGP table
Aggregateaggregate-address X maskany more-specific in the table
router bgp 65001
 aggregate-address 172.16.0.0 255.255.0.0
 aggregate-address 172.16.0.0 255.255.0.0 summary-only
 aggregate-address 172.16.0.0 255.255.0.0 as-set
  • summary-only suppresses the more-specifics.
  • as-set records the originating ASes as an AS_SET — without it the aggregate hides origins (black-hole risk on multi-origin).
  • atomic-aggregate (well-known discretionary) + aggregator mark the aggregation point.

One-Minute Summary & Self-Test

BGP in 60 seconds

Transport = TCP 179. Path-vector. Peer type = remote-as decides (eBGP 20 / iBGP 200).
eBGP : TTL 1 (ebgp-multihop) · next-hop changed to self · AS_PATH prepended.
iBGP : next-hop NOT changed (next-hop-self) · split horizon (no transit) → full mesh
        → route reflectors (clients only peer with RR) or confeds (sub-ASes, AD 200).

Best path (first difference decides):
  1 Weight (local)  2 Local-Pref (higher)  3 Locally originated
  4 AS_PATH (shorter)  5 Origin (i < e < ?)  6 MED (lower)
  7 eBGP > iBGP  8 IGP metric  9 Router ID.

Local-pref : AS-wide, iBGP-only, set in, default 100 — my outbound exit.
MED         : non-transitive, set out/judged in, same-AS only, default 0 — my inbound entry.
Communities : optional TRANSITIVE, send-community or stripped.
              NO_EXPORT (stays in AS) vs NO_ADVERTISE (stops here).
AS path     : prepend your OWN AS only.
Prefix-list : ge/le = length, implicit deny, 0.0.0.0/0 le 32 = everything.
Route-map   : seq, first match wins, deny = filter, direction in/out is local.
Aggregate   : aggregate-address (any more-specific) vs network (exact) · summary-only · as-set.
