# QoS Marking & Trust Boundaries

> **Level 21 · QoS** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Marking** writes a QoS value (**DSCP, CoS, IP precedence**) into the packet so downstream
devices apply consistent treatment, and the **trust boundary** is the point where the
network decides to **accept or re-mark** incoming markings. Marking is done **once at the
edge** and then **trusted / honored in the core**. The exam tests marking locations, the
trust boundary decision, and CoS↔DSCP mapping.

---

## 2. Core Concepts

### 2.1 Marking locations

| Layer | Field | Bits |
|-------|-------|------|
| L2 | 802.1p CoS | 3 |
| L3 | IP precedence | 3 |
| L3 | DSCP | 6 |
| MPLS | EXP | 3 |

- **DSCP (6 bits)** is the modern standard; **CoS** is LAN-only; **EXP** on MPLS.

### 2.2 The trust boundary

| Zone | Action |
|------|--------|
| Access edge | **untrusted** — re-mark/classify everything |
| Trusted ports (cameras/phones/APs) | **trust** the incoming CoS/DSCP |
| Core | **trust** DSCP, apply PHB (no re-mark) |

- The **trust boundary** is placed where traffic *enters* the network — decide trust vs
  re-mark at the access port.

### 2.3 Trust vs re-mark

| Mode | Behavior |
|------|----------|
| Trust | accept the existing CoS/DSCP as-is |
| Re-mark | overwrite with policy-derived value |

- On access ports you often **trust CoS but set DSCP**, or classify everything and re-mark.

### 2.4 Configuring trust and marking

```text
! trust CoS on an access port / switchport
mls qos trust cos
!
! set DSCP by class (marking)
policy-map MARK
 class VOICE
  set dscp ef
 class CAMERA
  set dscp af41
!
interface GigabitEthernet0/1
 service-policy input MARK
```

| Command | Effect |
|---------|--------|
| `mls qos trust cos` | trust incoming CoS |
| `mls qos trust dscp` | trust incoming DSCP |
| `set dscp` | write DSCP |
| `set cos` | write CoS |
| `service-policy input` | apply marking on ingress |

### 2.5 CoS ↔ DSCP mapping

| CoS | Typical DSCP usage |
|-----|--------------------|
| 0 | BE |
| 3 | call signaling |
| 4 | video (AF41) |
| 5 | voice (EF) |
| 6/7 | network control |

- Crossing L2/L3 needs a **CoS→DSCP mapping table**; trust CoS, set DSCP at the edge.

### 2.6 Marking best practice

| Rule | Detail |
|------|--------|
| Mark once | at the trust boundary / edge |
| Trust in core | core reads DSCP, no re-mark |
| Consistent PHB | queue by DSCP (EF, AF, CS) |
| Secure | untrusted ports re-mark |

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No marking | policy not attached | service-policy input |
| Wrong value | set statement | policy-map |
| Re-mark in core | trust boundary wrong | mls qos trust |
| CoS lost | L2/L3 boundary | cos-dscp mapping |
| Trusted untrusted | access port config | trust cos/dscp |

## 5. Exam Traps

- **Marking writes**; **classification reads** — two different acts.
- The **trust boundary** decides who is trusted and who gets re-marked (edge decision).
- Mark **once at the edge**, then **trust in the core** — the core never re-marks.
- CoS is **L2/LAN-only**; DSCP crosses L3 — map between them at the boundary.
- `mls qos trust cos` trusts CoS; `set dscp` marks.

## 7. One-Minute Mental Model

**Marking** stamps a QoS value (DSCP/CoS) onto the packet at the **edge**, and the **trust
boundary** is the access-point decision to accept (trust) or overwrite (re-mark) what came
in. After that single mark, the **core trusts the DSCP** and applies the PHB. If the field
crosses from L2 to L3, map **CoS→DSCP**; otherwise keep marking consistent and let the
core simply follow the ticket.
