# Modular QoS CLI (MQC)

> **Level 21 · QoS** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**MQC (Modular QoS CLI)** is the standard way to build QoS on Cisco routers. It separates
QoS into three building blocks — **class-map** (match), **policy-map** (action), and
**service-policy** (attach) — so classification, treatment, and application are reusable
and compose hierarchically. Every modern QoS config (marking, policing, shaping, queuing)
uses MQC. The exam tests the three blocks and their pairing rules.

---

## 2. Core Concepts

### 2.1 The three MQC blocks

| Block | Role | Command |
|-------|------|---------|
| **class-map** | match traffic | `class-map match-any/all NAME` |
| **policy-map** | define treatment | `policy-map NAME` |
| **service-policy** | attach to interface | `service-policy input/output NAME` |

- **class-map** = the *what*; **policy-map** = the *how*; **service-policy** = the *where*.

### 2.2 class-map matching

| Keyword | Logic |
|---------|-------|
| `match-all` | every criterion must match |
| `match-any` | any one criterion matches |
| `match dscp` | DSCP value(s) |
| `match access-group` | ACL |
| `match ip precedence` / `match cos` | L3/L2 marking |
| `match protocol` | NBAR (L7) |

```text
class-map match-any VOICE
 match dscp ef
class-map match-all STRICT
 match dscp af41
 match access-group name VIDEO-ACL
```

### 2.3 policy-map actions

| Command | Action |
|---------|--------|
| `set dscp` / `set cos` / `set precedence` | mark |
| `police` | enforce rate |
| `shape` | smooth rate |
| `bandwidth` | CBWFQ share |
| `priority` | LLQ strict priority |
| `queue-limit` | queue depth |
| `random-detect` | WRED |
| `fair-queue` | per-flow |

- A policy-map is a **named set of actions per class**.

### 2.4 Attaching with service-policy

| Direction | Command |
|-----------|---------|
| Ingress | `service-policy input NAME` |
| Egress | `service-policy output NAME` |
| Both | one policy per direction |

- **A policy is attached in one direction** — input or output, not both at once.

### 2.5 Class-default

| Item | Detail |
|------|--------|
| `class class-default` | matches all unmatched traffic |
| Always exists | catch-all class |
| Actions | shape/police/queue default |

- Unmatched traffic falls into **`class class-default`**.

### 2.6 Hierarchy (parent/child policies)

```text
policy-map PARENT
 class class-default
  shape average 10000000
  service-policy CHILD     ! nested
```

| Level | Policy |
|-------|--------|
| Parent | shapes the aggregate rate |
| Child | per-class sub-treatments |

- **Hierarchical MQC** nests a child policy inside a parent for shaping + per-class action.

## 3. Configuration / Commands

```text
class-map match-any VOICE
 match dscp ef
!
policy-map EDGE
 class VOICE
  priority 128
 class class-default
  fair-queue
!
interface GigabitEthernet0/1
 service-policy output EDGE
!
show class-map
show policy-map
show policy-map interface
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| No effect | policy not attached | service-policy input/output |
| Wrong class | match-all vs match-any | class-map |
| No match | wrong criteria | show class-map |
| Direction wrong | input vs output | policy attach |
| Need hierarchy | shape + queue | parent/child |

---

## 5. Exam Traps

- MQC = **class-map → policy-map → service-policy** (match, treat, attach).
- `match-all` vs `match-any` changes the matching logic.
- A service-policy attaches in **one direction** (input or output).
- Unmatched traffic hits **class-default**.
- **Hierarchical MQC** nests a child policy under a parent for shaping + per-class action.

## 7. One-Minute Mental Model

**MQC** is the three-part QoS recipe: pick traffic with a **class-map** (match-all vs
match-any), decide its treatment in a **policy-map** (set/police/shape/priority/bandwidth),
and glue it to an interface with **service-policy input/output**. Unmatched traffic falls
to **class-default**, and you can nest a **child policy** inside a parent for hierarchical
shaping. Get these three words and their direction right and every Cisco QoS config opens
up.
