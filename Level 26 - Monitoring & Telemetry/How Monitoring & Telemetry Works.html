📡 Monitoring & Telemetry — the whole picture

Two families: device & performance monitoring (SNMP, IP SLA, Syslog, streaming telemetry) and traffic monitoring (NetFlow, SPAN/ERSPAN, Wireshark). The big theme: pull (poll) vs push (stream).

The big idea: push vs pull

Pull (poll)

manager asks · SNMP GET · polling overhead

Push (stream)

device pushes · NetFlow · streaming telemetry · scalable

Streaming telemetry = push on change/interval (gRPC/gNMI over YANG) — the modern replacement for SNMP polling.

🖥️ SNMP

Management protocol over UDP 161 (poll) / 162 (traps). Data lives in the MIB, addressed by OIDs. Manager polls the agent.

Operations

GET

read an OID

GETNEXT

walk MIB

SET

write a value

TRAP/INFORM

push alert (A→M)

🪞 SPAN & ERSPAN — port mirroring

SPAN mirrors traffic from source ports to an analyzer on the same switch (one-way, local). RSPAN mirrors over a VLAN; ERSPAN encapsulates in IP/GRE across a routed network.

Scope picker (memorize)

SPAN
local · same switch
RSPAN
remote via L2 VLAN
ERSPAN
remote via IP/GRE
{{ spanVerdict.text }}

SPAN session

Build a session = source + destination. Keywords rx/tx/both set the mirrored direction. SPAN does NOT route.
monitor session 1 source interface GigabitEthernet0/1 both
monitor session 1 destination interface GigabitEthernet0/2
show monitor session 1
!
! ERSPAN (routed mirror)
monitor session 1 type erspan-source
 monitor session 1 source interface GigabitEthernet0/1 both
monitor session 1 destination
 erspan id 100
 erspan ip-address 192.0.2.10
 erspan origin-ip 198.51.100.1
show monitor session 1
ERSPAN needs `type erspan-source/destination`, `erspan id` + `erspan ip-address`; GRE overhead (~+50 bytes) — watch MTU.

🎯 IP SLA — synthetic probes

Generates synthetic probe traffic between routers to measure latency, jitter, loss, availability, MOS. Results can track (react) for routing decisions.

Probe types

ICMP echo

reachability

UDP jitter

voice/MOS

TCP connect

app checks

HTTP

web availability

Config pattern: `ip sla` + type + `frequency` + `ip sla schedule`; then `track N ip sla ... reachability` ties results to routing/object tracking.
ip sla 10
 icmp-echo 192.0.2.5
 frequency 60
 timeout 1000
ip sla schedule 10 life forever start-time now
track 1 ip sla 10 reachability
show ip sla statistics
show ip sla config
show track 1

🐛 Wireshark

Packet analyzer: capture, decode, filter, and analyze traffic. Reads pcap/pcapng, uses BPF capture filters + rich display filters.

Capture vs display filters (the trap)

Capture (BPF)

before capture · `tcp port 443`, `host 1.2.3.4` — limits what is stored

Display

after capture · `http.request`, `tcp.stream eq 0` — refines the view

Common display filters

ip.addr == X

host traffic

tcp.stream eq 0

one session

http.request

requests

Follow TCP Stream = analyze a full conversation. Statistics → conversations / protocol hierarchy. On-box on IOS-XE: `monitor capture`.
monitor capture CAP interface Gi0/1 both
monitor capture CAP buffer size 10240
monitor capture CAP start
show monitor capture CAP
