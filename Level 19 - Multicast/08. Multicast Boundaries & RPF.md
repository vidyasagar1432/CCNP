# Multicast Boundaries & RPF

> **Level 19 · Multicast** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

Two critical multicast control mechanisms keep multicast correct and confined:
**multicast boundaries** restrict where multicast may propagate (scoping), and the **RPF
(Reverse Path Forwarding) check** guarantees a loop-free, source-rooted delivery tree by
only forwarding packets that arrive on the interface the unicast table would use toward
the source. The exam tests both as distinct but complementary controls.

---

## 2. Core Concepts

### 2.1 RPF check — the loop guard

| Rule | Detail |
|------|--------|
| Forward | if packet arrived on the RPF interface |
| Drop | if it arrived on any other interface (RPF failure) |
| RPF interface | the interface the unicast RIB points at to reach the source |
| Result | loop-free, source-rooted tree |

- RPF uses the **existing unicast routing table**; multicast itself doesn't maintain its
  own topology.

### 2.2 Why RPF matters

| Benefit | Detail |
|---------|--------|
| Loop prevention | no packet returns to source |
| Tree correctness | only source-facing interface forwards |
| Failure type | silent drop (RPF failure) |
| Debug | `show ip rpf` |

- A packet on the wrong interface is **silently dropped** — the classic multicast
  troubleshooting symptom.

### 2.3 RPF and unicast-path asymmetry

| Case | Effect |
|------|--------|
| Equal unicast backbone | RPF fine |
| Asymmetric routing | RPF failure (packet arrives on non-RPF if) |
| Fix | MBGP alternate path / static RPF routes / tunnels |

- When unicast is asymmetric, you may need **MBGP** or a specific RPF path that differs
  from the data path.

### 2.4 Multicast boundaries

| Tool | Mechanism |
|------|-----------|
| **TTL boundary** | set TTL threshold on interface (e.g., `ip multicast ttl-threshold 16`) |
| **Group boundary** | `ip multicast boundary <acl>` blocks ranges at the interface |
| **Admin scoping** | 239/8 reserved for administratively scoped groups |
| **Auto-RP scope** | limits Auto-RP (224.0.1.39/40) propagation |

- Boundaries **scope** multicast — group ranges and TTL stay inside the network.

### 2.5 Configuration examples

```text
! TTL boundary - packets with TTL below threshold not forwarded
interface GigabitEthernet0/1
 ip multicast ttl-threshold 16
!
! Group boundary via ACL
access-list 10 deny   232.0.0.0 0.255.255.255
access-list 10 permit any
interface GigabitEthernet0/2
 ip multicast boundary 10
!
! multicasting scoping range
ip access-list standard SSM-LOCAL
 permit 239.0.0.0 0.255.255.255
```

| Command | Purpose |
|---------|---------|
| `ip multicast ttl-threshold` | TTL scoping |
| `ip multicast boundary` | group filter at interface |
| `239/8` | admin scoping range |

### 2.6 Admin scoping (239/8)

- **239.0.0.0/8** is reserved for **administratively scoped** multicast, never forwarded
  beyond the domain.

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| RPF drops | wrong inbound interface | show ip rpf |
| No forwarding OIL | drop / no receiver | show ip mroute |
| Multicast escaping | no boundary | TTL/group ACL |
| Loop | RPF disabled | RPF rules |
| Boundary blocking legit | ACL too broad | multicast boundary |

---

## 5. Exam Traps

- **RPF check** = forward only from the source-facing (unicast-RIB) interface; else drop.
- RPF uses the **unicast RIB** — asymmetric unicast breaks RPF unless MBGP/static fixes it.
- Boundaries: **TTL threshold** and **group boundary (ACL)** scope multicast.
- **239/8** = administratively scoped (won't leave the domain).
- RPF failure = **silent drop**, a common multicast troubleshooting trap.

## 7. One-Minute Mental Model

**RPF** is multicast's loop guard: forward only if the packet came in on the interface the
**unicast table** would use to reach the source — otherwise drop silently. **Boundaries**
are multicast's fence: a **TTL threshold** keeps low-TTL packets in, and a **group
boundary ACL** blocks group ranges at an interface, with **239/8** reserved for
administratively scoped groups. RPF decides *whether* to forward toward the tree;
boundaries decide *how far* multicast may travel.
