📡 Multicast — the whole picture

One-to-many delivery: IGMP = host→router membership, PIM = router-to-router tree building, RPF = the loop guard, snooping = the L2 pruning switch feature.

The two layers

Host → Router (LAN)

IGMP

v1/v2/v3 membership; v3 = source filtering (SSM)

Router → Router (network)

PIM

dense (flood) or sparse (join via RP)

Model choice

Dense (PIM-DM)

push / flood

assumes members everywhere; prunes; no RP

Sparse (PIM-SM)

pull / join

production default; RP required; (*,G)→(S,G)

Vocabulary to know cold

TermMeaning
(S,G)source-specific entry (shortest-path tree)
(*,G)any-source entry (shared/shared tree via RP)
RPFReverse Path Forwarding — loop guard
RPRendezvous Point — hub of PIM-SM
DRDesignated Router — speaks for the LAN
FHR / LHRFirst-Hop Router / Last-Hop Router
One-line mental model: hosts ask via IGMP, routers build trees with PIM, RPF keeps it loop-free, snooping stops L2 flooding.

🌊 PIM Dense (PIM-DM)

Assumes members everywhere — floods then prunes (push model). Builds a source-based (S,G) SPT with no RP.

Flood-and-prune cycle

1 source sends
2 flood to all PIM neighbors
3 leaf routers without members prune
4 state timeout → re-flood (every 3 min)

Graft = fast restore of a pruned branch when a new member appears below it.

State model

(S,G)

used — per-source tree

(*,G)

not used in DM

Prune state

branch cut — no receivers

🌱 PIM Sparse (PIM-SM) — production default

Nobody gets traffic until they explicitly join (pull model) through a Rendezvous Point (RP).

Pull model walk-through

1 receiver → IGMP report
2 DR joins (*,G) toward RP
3 RP → shared tree built
4 source registers to RP
5 last-hop → SPT switchover
Key: traffic flows only to those who asked.

Two trees

Shared tree — (*,G)

via RP, initial path

Shortest-path — (S,G)

source-direct, after switchover

Register process

1 source → FHR (multicast)
2 FHR → RP register (unicast, encapsulates)
3 RP → FHR register-stop
4 RP forwards down shared tree
Trap: the register message encapsulates the multicast packet in unicast to the RP. With spt-threshold 0 (the default) the LHR switches to the SPT immediately.

SPT switchover trigger

🔍 IGMP Snooping (the switch layer)

A Layer 2 (switch) feature that inspects IGMP reports and forwards multicast only out member ports — instead of flooding the whole VLAN.

Why it exists

Without snooping, a switch floods group traffic like broadcast. Snooping builds a per-group port table: member ports + the mrouter port.

How it works

1 host sends IGMP report
2 switch snoops it
3 records port as member
4 forwards group traffic only to member ports

Key terms

Mrouter port

facing the multicast router/querier

Member port

facing a host that reported the group

Snooping vs Proxying (the trap)

FeatureSnoopingProxying
Levelswitch inspects reportsswitch acts as proxy
Queriespasses throughswitch regenerates
StateL2 tablesL3-like state
Trap: snooping = switch/L2 and on by default on most Cisco switches. Snooping passes queries through; proxying terminates and regenerates them (different feature). Switch querier covers VLANs with no router.
ip igmp snooping                          ! global enable (default on)
ip igmp snooping vlan 10
ip igmp snooping querier                  ! switch acts as querier if no router

🅢 Source-Specific Multicast (SSM)

Trees rooted directly at a specific source (S,G) — no RP, no shared tree, no register process. RFC 4607.

SSM vs ASM

AspectASM (PIM-SM)SSM
Modelany source (*,G)source-specific (S,G)
RPrequirednone
Shared treeyes, then SPTnever
Registersource → RPnone
JoinIGMPv2 (*,G)IGMPv3 (S,G)
Address range224/4232.0.0.0/8
Inter-domaincomplex (MSDP)simple

How an SSM join works

1 Receiver → IGMPv3 (S,G) report → DR
2 DR → PIM (S,G) join toward source
3 Source → (S,G) SPT → receiver
Key: the receiver names both source and group in a single (S,G) join → the network builds one shortest-path tree — no RPT phase, no RP.

IGMP version requirement

VersionSupports SSM
IGMPv1/v2no (only (*,G))
IGMPv3yes (include/exclude source lists)
ip multicast-routing
ip pim ssm default                     ! SSM for 232/8 (RFC 4607)
! optionally custom range
ip pim ssm range SSM-POOL
access-list 10 permit 232.0.0.0 0.255.255.255
interface Gi0/1
 ip pim sparse-mode
 ip igmp version 3
show ip mroute ssm
show ip ssm
Trap: SSM = 232.0.0.0/8, IGMPv3 required, enable with ip pim ssm default. No RP → inter-domain multicast is simple (no MSDP).

🚧 Multicast Boundaries & RPF

Two distinct controls: RPF decides whether to forward toward the tree; boundaries decide how far multicast may travel.

RPF — the loop guard

Forward only if the packet arrived on the interface the unicast RIB points at for the source; otherwise silently drop (RPF failure). Uses the existing unicast table — multicast holds no separate topology.

RPF vs asymmetric unicast

Equal unicast

RPF fine

Asymmetric

RPF failure → fix with MBGP/static RPF/tunnels

Boundary tools

TTL boundary

ip multicast ttl-threshold 16

Group boundary

ip multicast boundary <acl>

Admin scoping

239.0.0.0/8 — never leaves the domain

Boundary selector

TTL threshold
blocks low-TTL packets leaving the network
Group boundary ACL
blocks group ranges at the interface
{{ bndVerdict.text }}
interface GigabitEthernet0/1
 ip multicast ttl-threshold 16        ! TTL scoping
access-list 10 deny 232.0.0.0 0.255.255.255
access-list 10 permit any
interface GigabitEthernet0/2
 ip multicast boundary 10             ! group filter
show ip rpf 10.1.1.1
show ip mroute
debug ip mpacket
Trap: RPF failure = silent drop. 239/8 = administratively scoped. Boundaries = TTL threshold + group boundary ACL. Asymmetric unicast breaks RPF unless MBGP/static fixes it.

🏆 PIM DR & Assert

On a multi-access LAN with several PIM routers: the DR is elected to represent the hosts; Assert resolves duplicate (S,G) forwarding.

DR vs Assert (memorize the difference)

DR = who speaks for hosts

sends IGMP/PIM joins · registers the source (FHR) · last-hop join

Assert = who forwards the stream

picks one forwarder for a duplicated (S,G) on the LAN

DR election

1 highest PIM neighbor priority wins (default 1)
2 tie → highest IP address wins
3 winner handles joins/IGMP/register

Assert winner

1 lower route preference (admin distance) wins
2 then lower metric to source
3 tie → highest IP wins

Assert selector

Lower metric
better path → wins
Equal metric
higher IP → wins
{{ assertVerdict.text }}
Trap: DR = priority then highest IP (ip pim dr-priority). Assert winner = lower metric to source, higher IP on tie. DR removes membership ambiguity; Assert removes forwarding duplication.
interface GigabitEthernet0/1
 ip pim sparse-mode
 ip pim dr-priority 200        ! influence DR election

show ip pim neighbor
show ip pim assert
