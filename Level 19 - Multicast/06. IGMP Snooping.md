# IGMP Snooping

> **Level 19 · Multicast** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**IGMP snooping** is a **switch (Layer 2)** feature that inspects **IGMP membership
messages** as they pass through and builds forwarding tables so multicast is sent **only
out ports that have members** — instead of flooding group traffic to the whole VLAN. The
exam tests the querier/mrouter port concept, snooping table commands, and the proxying vs
snooping distinction.

---

## 2. Core Concepts

### 2.1 Why snooping exists

| Problem | Without snooping |
|---------|------------------|
| Flooding | multicast flooded to every port |
| Waste | CPUs get unwanted traffic |
| Isolation | no host-level filtering |

- Without snooping, a switch floods group traffic like broadcast — **snooping stops that**.

### 2.2 How snooping works

| Step | Action |
|------|--------|
| 1 | host sends IGMP report |
| 2 | switch listens (snoops) the report |
| 3 | switch records the port as a member |
| 4 | switch forwards group traffic only to member ports |

- The switch builds a **CAM/forwarding table per group → ports**.

### 2.3 Key terms

| Term | Meaning |
|------|---------|
| **Mrouter port** | port facing the multicast router/querier |
| **Member port** | port facing a host that reported the group |
| **Querier** | router sending IGMP queries |
| **Static mrouter** | manually defined router port |

- The switch forwards group traffic out **member ports + the mrouter port**.

### 2.4 IGMP snooping vs proxying (the trap)

| Feature | Snooping | Proxying |
|---------|----------|----------|
| Level | switch inspects reports | switch acts as proxy |
| Forward | per-port tables | summarizes membership |
| Queries | passes through | switch regenerates |
| State | L2 tables | L3-like state |

- **Snooping passes queries through**; **proxying terminates and regenerates them**.

### 2.5 Configuration and query suppression

| Command | Purpose |
|---------|---------|
| `ip igmp snooping` | global enable (default on most) |
| `ip igmp snooping vlan 10` | enable per VLAN |
| `ip igmp snooping querier` | switch can be querier if no router |
| `no ip igmp snooping` | disable |
| `ip igmp snooping mrouter learn pim` | learn mrouter from PIM |

- When no multicast router exists, the **switch querier** can act as the IGMP querier.

### 2.6 Verification

```text
show ip igmp snooping
show ip igmp snooping groups
show ip igmp snooping mrouter
show mac address-table multicast
```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Group floods all ports | snooping disabled | show ip igmp snooping |
| No forwarding | mrouter port wrong | snooping mrouter |
| Host not in table | report not seen | snooping groups |
| Missing querier | no router | snooping querier |
| Inter-VLAN leak | VLAN membership | vlan config |

---

## 5. Exam Traps

- IGMP snooping is a **switch/L2** feature; IGMP itself is host→router (**L3**) — note 01.
- Snooping **passes queries through**; proxying is a different (L3) feature.
- Group traffic forwards out **member + mrouter ports** only.
- **Snooping is on by default** on most Cisco switches.
- The **switch querier** covers VLANs with no multicast router.

## 7. One-Minute Mental Model

**IGMP snooping** is the switch's "peeking" version of IGMP: the switch reads IGMP
reports on a VLAN, writes a per-group port table (member ports + the **mrouter port**),
and forwards multicast only where hosts asked — killing the flooding broadcast model. It
passes queries through (that's **proxying** that regenerates them, a different feature) and
is on by default; if a VLAN has no router, the **switch querier** takes over.
