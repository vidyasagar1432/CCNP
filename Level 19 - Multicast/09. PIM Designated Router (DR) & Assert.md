# PIM Designated Router (DR) & Assert

> **Level 19 · Multicast** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

On a multi-access **LAN segment** with several PIM routers, multicast needs rules to
avoid duplication and ensure who acts for hosts: the **[[PIM DR|Designated Router (DR)]]** elected on
the segment takes responsibility for IGMP/PIM joins and (in sparse mode) sending register
messages, while the **PIM Assert** mechanism resolves **duplicate forwarding** when two
routers both forward the same `(S,G)` onto the LAN. The exam tests the DR election and the
assert winner rule.

---

## 2. Core Concepts

### 2.1 Why DR and assert are needed

| Problem | Solution |
|---------|----------|
| Multiple routers on a LAN | elect a **DR** to act for hosts |
| Duplicate `(S,G)` on the LAN | **Assert** picks one forwarder |

- Two routers both forwarding the same stream would duplicate frames — the **assert**
  picks a single forwarder.

### 2.2 DR election

| Factor | Rule |
|--------|------|
| Priority | **highest PIM neighbor priority wins** (default 1) |
| Tie-break | **highest IP address wins** |
| Sparse mode | DR sends IGMP/PIM joins and is the registerer |
| Hello | uses `ip pim dr-priority` |

- Configure priority with **`ip pim dr-priority <n>`** on the interface.

### 2.3 DR role in PIM-SM

| Task | Who |
|------|-----|
| Sends join/IGMP on LAN | DR |
| Registers source traffic | First-Hop Router (FHR = DR on source LAN) |
| Receives packet to RP | DR (register) |
| Last-hop join to SPT | DR (LHR) |

- The DR is the **single representative** for the segment — its priority/IP decides it.

### 2.4 PIM Assert

| Item | Detail |
|------|--------|
| Trigger | two routers forwarding same `(S,G)` on a LAN |
| Purpose | prune one duplicate forwarder |
| Winner | based on **assert metric** (preference + metric) |
| Tie-break | lower metric path; then higher IP |

- The **assert winner** keeps forwarding; the loser prunes the `(S,G)` on that interface.

### 2.5 Assert metric criteria

| Factor | Determines winner |
|--------|-------------------|
| Route preference (admin distance) | lower wins |
| Metric to source | lower wins |
| Tie (same path) | **highest IP address wins** |

- A router with a **better (lower) metric to the source** wins the assert.

```text
show ip pim interface
show ip pim neighbor
show ip pim assert
show ip mroute

```

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Wrong DR | priority | show ip pim interface |
| Duplicate traffic | no assert yet / metric equal | show ip pim assert |
| Join not sent | not DR | neighbor priority |
| Register fails | FHR not DR | pim priority |
| Assert flapping | equal metric | tie-break IP |

- Duplicate multicast on a LAN usually means the **assert** hasn't resolved a winner yet.

---

## 5. Exam Traps

- **DR = elected by priority then highest IP**; it acts for hosts on the LAN (joins/IGMP/register).
- **Assert = picks one forwarder** for a duplicated `(S,G)` on the same LAN.
- Assert winner = **lower metric to source**; tie-break = **higher IP**.
- Configure DR priority with **`ip pim dr-priority`**.
- DR is about **who speaks for hosts**; Assert is about **who forwards the stream**.

## 7. One-Minute Mental Model

On a shared LAN, the **DR** is the segment's spokesperson — picked by **priority then
highest IP** — and handles IGMP/joins and (in sparse mode) registering the source. If two
routers both start forwarding the same `(S,G)` onto the LAN, the **Assert** mechanism
keeps only the one with the **better (lower) metric to the source** (higher IP on a tie)
and the other prunes. DR removes *membership* ambiguity; Assert removes *forwarding*
duplication.
