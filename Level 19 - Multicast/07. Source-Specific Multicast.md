# Source-Specific Multicast (SSM)

> **Level 19 · Multicast** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**[[Source-Specific Multicast|Source-Specific Multicast (SSM)]]** builds distribution trees rooted directly at a
**specific source `(S,G)`** — there is **no RP, no shared tree, and no register process**.
Receivers use **IGMPv3** to join `(S,G)` explicitly (`include` source list), and PIM-SSM
builds a shortest-path tree from the source. SSM is the RFC 4607 model that avoids the
RP/register complexity of PIM-SM and simplifies inter-domain multicast.

---

## 2. Core Concepts

### 2.1 SSM vs ASM (the core table)

| Aspect | ASM (PIM-SM) | SSM |
|--------|--------------|-----|
| Model | any source `(*,G)` | source-specific `(S,G)` |
| RP | required | **none** |
| Shared tree | yes then SPT | never |
| Register | source → RP | none |
| Join | IGMPv2 `(*,G)` | **IGMPv3 `(S,G)`** |
| Address range | 224/4 | **232.0.0.0/8** |
| Inter-domain | complex (MSDP) | simple |

- SSM eliminates **RP + shared tree + register** entirely.

### 2.2 The SSM address range

- SSM operates in **232.0.0.0/8** (RFC 4607) — receivers join specific `(S,G)` pairs in
  this range.
- Outside 232/8, standard ASM (PIM-SM) behavior applies.

### 2.3 How an SSM join works

```
Receiver --IGMPv3 (S,G) report--> DR
DR --PIM (S,G) join--> toward source
Source --(S,G) SPT--> receiver
```

- The receiver names **both source and group** in a **single (S,G)** join; the network
  builds one **shortest-path tree** from that source — no RPT phase.

### 2.4 IGMPv3 requirement

| Version | Supports SSM |
|---------|--------------|
| IGMPv1/v2 | no (only `(*,G)`) |
| IGMPv3 | **yes (`include`/`exclude` source lists)** |

- **IGMPv3** is mandatory on the receiver LAN — it sends `(S,G)` membership reports.

### 2.5 Configuration

```text
ip multicast-routing
! enable SSM (default group range 232/8)
ip pim ssm default
!
! optionally specify range
ip pim ssm range SSM-POOL
access-list 10 permit 232.0.0.0 0.255.255.255
!
interface Gi0/1
 ip pim sparse-mode
 ip igmp version 3
```

| Command | Purpose |
|---------|---------|
| `ip pim ssm default` | enable SSM for 232/8 |
| `ip pim ssm range` | use a custom range |
| `ip igmp version 3` | IGMPv3 on access link |

### 2.6 Benefits of SSM

| Benefit | Detail |
|---------|--------|
| No RP | simpler design |
| No shared tree | immediate SPT |
| No register | less overhead |
| Inter-domain | no MSDP needed |
| Security | source authentication (only known source) |
| Latency | shortest path from start |

## 5. Exam Traps

- SSM = **source-specific `(S,G)`**, no RP / shared tree / register.
- Uses the **232.0.0.0/8** group range (RFC 4607).
- Requires **IGMPv3** on the receiver segment.
- Enable with **`ip pim ssm default`**.
- SSM makes **inter-domain multicast simple** — no MSDP.

## 7. One-Minute Mental Model

**SSM** is the "no-RP multicast": receivers join a **specific source `(S,G)`** via
**IGMPv3**, and PIM builds a shortest-path tree straight to that source in the **232/8**
range. There's no rendezvous point, no shared tree, and no register burst — so it's faster
and far simpler, especially across domains. If you see IGMPv3 + 232.x + "(S,G)" with no RP,
you're in SSM territory.
