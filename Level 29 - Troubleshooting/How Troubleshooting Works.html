🩺 Troubleshooting — a systematic approach

Troubleshoot bottom-up (L1 → L2 → L3 → services) and verify one layer before the next. Detect the symptom, isolate the layer/technology, check both directions, then fix and verify.

The systematic method

1 Define symptom
2 Pick layer/tech
3 Verify up the chain
4 Isolate the segment
5 Fix + verify
Verify EVERY layer from L1 up. A layer-3 route exists ≠ the path works — check return path, ACLs, and NAT.

Rule out the physical first, then data-link, then network. Match the symptom to its layer before touching config.

🔌 Switching: VLAN / STP / EtherChannel

L2 faults split into VLAN membership, spanning-tree, and link aggregation. Pick the failing piece.

VLAN
exists · access · trunk
STP
root · roles · loops
EtherChannel
bundle · modes
{{ swVerdict.text }}

VLAN checks

  • VLAN must exist first (`show vlan`)
  • Trunk allowed list gates crossing
  • Native VLAN must match both ends
  • MAC table = ground truth of VLAN membership
  • Cross-VLAN DHCP → `ip helper-address`

STP checks

  • Blocking is normal; loops are the failure
  • Root = lowest priority, then MAC
  • PortFast + BPDU Guard on access ports
  • Root Guard = wrong root; Loop Guard = silent failure
  • TC storm = flapping port flushes MACs

`show etherchannel summary` shows P(in bundle)/I(standalone)/S(suspended)/D(down). passive+passive and auto+auto never bundle. Members must match speed, duplex, VLAN, mode.

📊 Performance Analysis

Isolate latency, throughput, jitter, and loss and tie them to the network path with ping, traceroute, IP SLA, NetFlow, and packet analysis.

Key metrics

Latency

RTT delay = ser + prop + process + queue

Jitter

delay variation (≠ latency)

Loss

dropped %

Throughput

delivered bits/sec

PatternMeaning
Constant high latencyserialization / distance
Spiking latencyqueueing / congestion
Burst losscongestion / drops
One-way highasymmetric path
Triggered by TCPwindow limiting throughput
Latency = 4 components. Jitter is VARIATION, not level. TCP window caps throughput independently of link bandwidth. IP SLA = active measurement. Baseline before isolating.

🧭 The systematic workflow

1 Baseline
2 Measure latency/loss
3 Identify segment
4 Capture
5 Confirm fix
Work methodically: define the symptom → pick the layer → verify up the chain → isolate the segment (traceroute pinpoints the failing hop) → fix → re-verify. Always check the return path.
