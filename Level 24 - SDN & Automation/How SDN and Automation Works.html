⚙️ SDN & Automation — the whole picture

Two big ideas: SDN (separate control from data, centralize the brain) and automation (program the network via APIs/data models/tools). The stack: DNA Center + SD-Access (LISP/VXLAN) for the fabric, REST/RESTCONF/NETCONF over YANG to talk to devices, and Python/Ansible/Terraform/Git to drive it all.

🔀 VXLAN — data-plane overlay

Encapsulates L2 frames in UDP (4789) over the underlay, scaling VLANs to 16 million VNIs and stretching L2 domains across L3. The data plane of SD-Access.

Why VXLAN (escapes the VLAN limit)

Problem

4094 VLANs (12-bit) · L2 can't stretch L3 · multi-tenant

Answer

16M VNIs (24-bit) · MAC-in-UDP overlay · VNI = tenant

VLAN vs VXLAN (the trap)

VLAN
12-bit · 4094 · L2-domain · switch transport
VXLAN
24-bit VNI · 16M · overlay L3 · UDP/IP transport

🗺️ LISP — control-plane overlay

Separates identity (EID) from location (RLOC): hosts keep stable IDs while mapping to current locations via a map server/control plane. The control plane of SD-Access.

EID vs RLOC (the core split)

EID
endpoint identity (host IP) — travels
RLOC
routing locator (site IP) — current location
{{ lispVerdict.text }}

LISP roles

ITR

ingress tunnel router (edge)

ETR

egress tunnel router (edge)

MR/MS

map resolver/server (control)

PxTR

proxy to non-LISP

Mapping flow

1 ITR needs a destination
2 map-request to MR/MS
3 MS returns EID → RLOC
4 ITR encapsulates to ETR
Control plane = map lookup; data plane = encapsulation. LISP maps EIDs so hosts roam with the same IP.

🔌 REST API

An HTTP-based API style: resources have URLs and actions are HTTP verbs; data rides as JSON. Controllers (DNA Center, vManage) expose REST — making the network scriptable.

📦 RESTCONF · NETCONF · YANG

The model-driven way to configure devices. YANG is the shared data model; RESTCONF and NETCONF are two protocols that operate on it.

Protocol picker (the core contrast)

RESTCONF
RFC 8040 · HTTP(S) · JSON/XML · stateless
NETCONF
RFC 6241 · SSH · XML RPC · candidate
{{ yangVerdict.text }}

RESTCONF vs NETCONF (memorize)

AspectRESTCONFNETCONF
TransportHTTP(S)SSH
EncodingJSON/XMLXML
StyleHTTP verbsRPCs (<get>/<edit-config>)
Statestatelessstateful
Candidatelimitedyes — stage & commit
RESTCONF = HTTP + JSON (simpler); NETCONF = SSH + XML/RPC (richer, transactional). Pick RESTCONF for simplicity, NETCONF for power.

YANG data model (shared schema)

module

namespace

container

group of nodes

list

leaf

Standard models: ietf-interfaces, ietf-ip, Cisco-IOS-XE-native. Typed leaves = automatic validation.

📄 Data Formats — JSON · XML · YAML

The payloads that carry config and state. JSON (modern API default), XML (NETCONF/legacy), YAML (Ansible/readable).

Format picker

JSON
compact · { } [ ] · REST
XML
tags · well-formed · NETCONF
YAML

{{ fmtVerdict.text }}

Examples & key rules

FormatStructureRules / gotchas
JSON{ } object, [ ] array, "key": valuedouble-quoted keys · no trailing commas
XML<tag>value</tag>, attr="v"well-formed · one root · case-sensitive · escape & < >
YAMLkey: value, - item (indent)spaces NOT tabs · same indent level · quote special chars
JSON keys double-quoted & no trailing commas (parse fails otherwise). YAML tabs/mixed indent = parse error. JSON = light/modern, XML = verbose/strict, YAML = human-readable.
! JSON (Python)

! XML (Python)

! YAML (Python)
import yaml
data = yaml.safe_load(text)  # YAML -> dict/list
