What is EIGRP?

EIGRP (Enhanced Interior Gateway Routing Protocol) is Cisco's routing protocol for interior networks. It is technically classified as an advanced distance-vector protocol — often called a "hybrid" because it borrows ideas from link-state protocols without being one.

Distance-vector behavior
Exchanges routes only with directly connected neighbors. No link-state database, no LSA floods, no SPF algorithm.
Link-state ideas
Maintains a detailed topology table of all learned paths and performs loop-free path selection with DUAL (Diffusing Update Algorithm).

Transport facts — memorize these

FactValueTrap
IP protocol number88Not TCP port 88, not UDP port 88
IPv4 multicast224.0.0.10Not 224.0.0.5 (OSPF), not 224.0.0.9 (RIPv2)

Exam trap: EIGRP uses IP protocol 88. That is an IP protocol number, not a port. "RTP" here is EIGRP's Reliable Transport Protocol — completely unrelated to the RTP used for audio/video.

Packets & the Reliable Transport Protocol

RTP = Delivers. DUAL = Decides. RTP delivers every EIGRP packet; DUAL decides what routing information is needed.

Neighbors & Adjacency

EIGRP discovers neighbors with Hellos, but forming an adjacency is stricter than just hearing Hellos.

Hello & hold timers

Interface typeHelloHold
Broadcast / most point-to-point5 s15 s
NBMA (e.g. Frame Relay)60 s180 s

Hold is typically 3 × Hello. Each router advertises its hold time, and the receiver uses it.

Hello timers do NOT need to match between neighbors — unlike OSPF.

What must match

  • Same EIGRP AS / process number
  • K-values (metric weights)
  • Network/interface compatibility (primary addressing)
  • Authentication, if configured
K-value mismatch → adjacency does NOT form. Hello timer mismatch → adjacency can still form. This is a classic exam contrast.

The EIGRP Metric

K-values and the composite metric

Default classic EIGRP K-values: K1=1, K2=0, K3=1, K4=0, K5=0. With the defaults, only bandwidth and delay matter:

Metric (classic) = 256 × ( 10,000,000 / minimum bandwidth (kbps)  +  sum of delays (µs) / 10 )

Wide metrics (named mode / EIGRP for IPv6) use 65536 instead of 256. K-values must match between neighbors or the adjacency fails.

DUAL — the core algorithm

Diffusing Update Algorithm: loop-free route selection and fast convergence, entirely from the topology table.

The three key terms

TermMeaning
SuccessorNeighbor providing the best path (lowest total metric). Installed in the routing table.
FD (Feasible Distance)Our total metric to the destination through the successor: local cost to neighbor + neighbor's RD.
RD / AD (Reported/Advertised Distance)Metric the neighbor reports for reaching the destination itself.
FD = Full Distance from ME to the destination.
RD = Reported Distance from the NEIGHBOR to the destination.

Feasibility condition

RD(neighbor) < FD(current successor)

Must be strictly less than:

ConditionResult
RD < FD✅ Feasible Successor — loop-free backup
RD = FD❌ Not a feasible successor
RD > FD❌ Not a feasible successor

Why loop-free? If B reports RD(B→X) < FD(A→X), then B's own distance to X is already smaller than A's — B can't loop back through A, so it's safe.

Advanced Features

Named Mode

Modern configuration style: router eigrp CCNP + address-family ipv4 unicast. One process handles IPv4 and IPv6 address families; supports wide metrics, 128-bit router IDs, and per-AF configuration.

EIGRP for IPv6

Runs per address family (address-family ipv6). Uses link-local addressing, no broadcasts, no auto-summarization, and a mandatory router ID.

Stub routers

eigrp stub connected static summary — the stub advertises only those route types and never relays queries, shrinking the query domain and preventing SIA. Exam-design answer for query propagation problems.

Authentication

MD5 or HMAC-SHA-256 with key chains. Keys must match on both ends or the adjacency fails. Protects against route injection and neighbor spoofing.

Variance

variance N lets alternate paths whose metric is up to N × FD be used for load sharing — but each path must still satisfy the feasibility condition (RD < FD).

Unequal-cost load balancing

The result of variance: traffic split proportionally to metrics across multiple successors. Up to 4 paths default (maximum-paths can raise it). EIGRP's flagship advantage over OSPF's equal-cost-only default.

One-Minute Summary & Self-Test

The whole protocol in 60 seconds

EIGRP  = advanced distance-vector, IP protocol 88, multicast 224.0.0.10, no TCP/UDP.
RTP    = Delivers (Update/Query/Reply reliable; Hello/ACK unreliable).
DUAL   = Decides (loop-free paths from the topology table).

Successor = best path (lowest total metric) → FD = our total metric to dest.
RD        = what the neighbor reports for the destination.

Feasibility condition:  RD < FD  → Feasible Successor
                        RD = FD  → NO        ✗
                        RD > FD  → NO        ✗

Successor fails:
    FS exists → promote FS → FAST, no queries.
    No FS     → ACTIVE   → queries → replies → diffusing computation.

Passive = stable.  Active = DUAL is searching.  SIA = replies never came.

Hello timers: may differ.   K-values: must match.
Default metric: bandwidth + delay (K1=1, K2=0, K3=1, K4=0, K5=0).
