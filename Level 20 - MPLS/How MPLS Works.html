🏷️ MPLS — the whole picture

Multiprotocol Label Switching forwards using short fixed-length labels instead of IP longest-prefix lookups. Labels sit in a 2.5 shim. Enables traffic engineering (TE), L3VPN, and pseudowires (L2VPN).

Where the shim sits

L3

IP

L2.5

MPLS shim (labels)

L2

Ethernet / PPP

The core idea (memorize)

CE -- PE (LER) -- P (LSR) -- P -- PE (LER) -- CE
        push            swap/swap            pop

Edge routers push/pop; core routers only swap. Forwarding inside the core is label-based — the core stays customer-route-free.

Domain vocabulary

TermMeaning
LSPlabel-switched path (the tunnel, ingress→egress LER)
LER / PEedge — push/pop + VRF + MP-BGP
LSR / Pcore — swap only, LFIB-driven
FECclass of packets sharing a label
LFIBlabel forwarding table (in-label → out-label)
One-liner: MPLS = label switching, edge pushes/pops, core swaps; needs CEF + LDP; basis for L3VPN / L2VPN / TE.

🏷️ MPLS Labels — the shim header

A 20-bit label in a 32-bit shim between L2 and L3. Each router swaps the top label and forwards.

The 32-bit shim (memorize the bit counts)

Label · 20 bits
Exp 3
S 1
TTL 8
FieldBitsMeaning
Label20forwarding value
Exp3QoS / class
S1bottom of stack
TTL8hop limit

Label value ranges

ValueUse
0explicit null (keep QoS/Exp at egress)
1router alert (control traffic)
3implicit null (PHP — pop before egress)
16 – 1,048,575normal labels

Label operations

Push

ingress LER — add shim

Swap

core LSR — replace top

Pop

penultimate/egress — remove

PHP (penultimate hop popping): the last core hop pops the label (implicit null 3) so the egress does pure IP delivery. Use explicit null 0 when the egress still needs to read Exp for QoS.

TTL handling mode

Pipe mode
TTL NOT decremented — hides the core
Uniform mode
TTL decrements normally
{{ ttlVerdict.text }}
Trap: shim = label 20 + exp 3 + S 1 + TTL 8. S bit marks bottom of stack. VPN = two-label stack (transport + service). PHP pops before egress; explicit null 0 preserves QoS.

⬛ LSR — Label Switch Router (P)

Lives in the core. Forwards by swapping the top label based on the LFIB — no IP lookup, no customer routes.

Forwarding flow

1 receive labeled packet
2 LFIB lookup (in label)
3 swap label
4 forward out interface
Only the top label is examined and swapped. The core is routing-free of customer prefixes — the scale win.

LDP — label distribution

Protocol

🎯 FEC — Forwarding Equivalence Class

A class of packets that share the same forwarding treatment — same next hop, same path, same label. MPLS assigns one label per FEC.

🧊 VRF — Virtual Routing and Forwarding

A per-tenant virtual routing table + forwarding instance on a PE. Each VRF has its own RIB, FIB (CEF), interfaces, and routes — customers isolated on shared hardware.

🔁 MP-BGP — Multiprotocol BGP (VPNv4)

Carries VPN routes between PEs using address families and the RD + RT model. The VPNv4 address family is how the control plane builds L3VPNs.

Address families

AFCarries
ipv4 unicastnormal BGP
ipv4 multicastmulticast NLRI

The VPNv4 route

RD(8B) + IPv4(32B) + Label — RD + prefix = globally unique; label = the VPN FEC; RT = membership.

RT policy

tags routes leaving the VRF

RTs ride as extended communities and create the VPN topology (full-mesh / extranet / hub-spoke).

🔗 MPLS VPN (L3VPN)

Private, isolated customer connectivity over a shared SP core. Each customer has a VRF on the PE; the core carries traffic in a two-label stack.

The roles

CE

customer router, PE-facing

PE

provider edge — VRF + MP-BGP

P

provider core — label switch

The two-label stack (memorize)

Top label — transport

reaches egress PE (LDP)

Inner label — service (VPN)

which VRF/CE at egress

The core only looks at the top label; the egress PE uses the inner one.

End-to-end flow

CE1 --(IP)--> PE1: push [service|transport]
               P  : swap transport label
               PE2: pop, read service label -> VRF -> CE2
1 CE1 sends IP
2 PE1 VRF lookup → push labels
3 P swaps top label
4 PE2 pop + service label → CE2
