🌐 OSPF Basics (v2 & v3)

OSPF (Open Shortest Path First, RFC 2328) is an open-standard, link-state IGP with AD 110. Routers flood LSAs to build a shared LSDB, then each runs Dijkstra SPF to compute its shortest-path tree — fast convergence, loop-free by construction.

🪪 Router ID — who is this router

The 32-bit Router ID (RID) uniquely identifies an OSPF router in the LSDB — it appears in LSA headers, Hellos, and DR/BDR election. Stable RIDs prevent duplicate-router confusion.

Election order (memorize)

1 Explicitly configured router-id
2 Highest IPv4 loopback
3 Highest IPv4 physical interface
4 None → OSPF may refuse to start
Trap: RID election uses highest, not lowest. And changing router-id needs clear ip ospf process to take effect.

RID & operations

  • Neighbor identity in show ip ospf neighbor = RID, not interface IP.
  • DR/BDR tie-break uses highest RID when priority is equal.
  • Duplicate RIDs → neighbors flap / never form — RID must be unique per area/domain.
  • OSPFv3 still needs a 32-bit RID even with no IPv4 — configure it manually.

💠 DR / BDR

On multi-access (broadcast/NBMA) networks, a Designated Router (DR) and Backup DR (BDR) cut full adjacencies from N×(N−1)/2 down to N. Point-to-point links elect no DR/BDR. Election is priority first, then RID.

Election rules

1 Highest interface priority (0–255, default 1)
2 Tie → highest Router ID
3 Election is non-preemptive
Non-preemptive: a higher-priority router joining later does not take over until a full election reset (link down / OSPF restart).

Roles & failure

RoleAdjacency behavior
DRFull with BDR + all DROthers; floods to segment
BDRFull with DR + DROthers; silent until DR fails
DROther2-Way with DROthers; Full with DR+BDR only
DR dies → BDR becomes DR → a new BDR is elected among DROthers. DROthers never send LSAs to each other — via DR/BDR (multicast 224.0.0.6).
Trap: priority 0 = never a DR/BDR. P2P = no DR at all (straight to Full). Both election criteria are "highest", don't invert.

🗂️ LSA Types

LSAs (Link State Advertisements) are the building blocks of the LSDB. Each type describes a different part of topology or reachability — who originates it and where it lives matters. Memorize Types 1–7.

E1 vs E2: E2 = external cost only (default); E1 = total cost includes the path cost to the ASBR. Same idea for N1/N2.
Traps: Type 2 is originated by the DR, not every router. Type 4 tells you how to reach the ASBR. Type 5 is domain-wide but blocked in stub areas (why NSSA/Type 7 exists). Type 7→5 translation happens at the ABR, not the ASBR.

🌳 SPF Algorithm (Dijkstra)

OSPF runs Dijkstra's shortest-path-first (SPF) over its LSDB, rooted at itself. Because every router has the same LSDB, each derives the same loop-free shortest paths deterministically. SPF runs per-area.

FunctionResponsibility
Floodingdistributes LSAs (facts) across the area

Fast convergence: timers throttle spf (initial/hold/max) + Incremental SPF (ISPF) recalc only affected subtrees. A flap in one area does not recompute all areas.

🗺️ Areas & Backbone

Areas partition the domain to bound flooding and SPF. Each keeps its own LSDB; Area 0 (backbone) is mandatory transit and all areas must connect to it (directly or via virtual link).

Router roles

RoleDefinition
Internal routerall interfaces in one area
ABRinterfaces in ≥2 areas, at least one is area 0
Backbone routerhas an interface in area 0
ASBRredistributes routes from outside OSPF

Why areas help (scale story)

Without areasWith areas
one giant LSDB domain-wideper-area LSDB only
every flap → full-domain SPFflap contained to its area
no summariesType-3/4/5 summaries at ABR
high CPU / memorybounded CPU / memory

LSA flow across areas

Internal (Type 1/2) --> ABR generates Type 3 --> next area
ASBR generates Type 5 --> flooded domain-wide (except stubs)
ASBR in NSSA --> Type 7 --> ABR converts to Type 5
Trap: ABR = interface in ≥2 areas, one in area 0 — the standard exam definition. All areas must touch area 0 (or virtual link). Area can be a number or dotted-decimal, and all routers in an area must agree on the area ID + parameters.

🧱 Stub & Totally Stubby Areas

A stub area blocks Type 5 (external) LSAs; the ABR injects a default route so outbound traffic still works. A totally stubby area also blocks Type 3 inter-area summaries — the smallest possible LSDB.

🔁 NSSA — stub + local ASBR

A Not-So-Stubby Area (NSSA) is a stub area that allows an ASBR: external routes enter as Type 7 LSAs (flooded only in the NSSA), then the ABR translates them to Type 5 at the exit. It still blocks inbound Type 5.

Type 7 → Type 5 translation flow

ASBR redistributes → Type 7 (NSSA only)
ABR sees Type 7 → generates Type 5
Domain Type 5 flooded to the rest of OSPF
P-bit (propagate bit) marks which Type 7 LSAs are eligible to be translated. If multiple ABRs exist, only one translates (the elected one).

🪢 Virtual Links

A virtual link is a logical OSPF tunnel that connects an isolated area to Area 0 through a transit area — or patches a discontiguous Area 0. It is a last-resort repair, not a design tool.

The two use cases

Isolated area → Area 0

an area physically separated from the backbone gets a virtual link through a transit area.

Discontiguous Area 0

a split backbone is stitched back together via a virtual link.

Config (on BOTH endpoint ABRs)

router ospf 1
 area 2 virtual-link 1.1.1.1        ! 1.1.1.1 = the peer ABR's router-id

! Auth on the virtual link
 area 2 virtual-link 2.2.2.2 authentication message-digest
 area 2 virtual-link 2.2.2.2 message-digest-key 1 md5 secret

Identified by router-IDs, not interface IPs. Cost = the transit-area path cost between the two ABRs.

Constraints checklist

  • Transit area must be standard — not stub / totally stubby / NSSA.
  • Area 0 cannot be the transit area.
  • Both endpoints must be ABRs.
  • Repair mechanism only — design answers should avoid it unless fixing a break.
Verify: show ip ospf virtual-links — state shows Up / DOWN.

🔐 OSPF Authentication

OSPF authentication validates the origin of Hello / LSA packets, stopping rogue routers or injected LSAs. OSPFv2 supports null, plaintext, and MD5/HMAC-SHA; OSPFv3 has no OSPF-level auth — it relies on IPv6 AH/ESP (IPsec).

OSPFv2 authentication types

TypeValueSecurityNotes
Null0nonedefault
Plaintext (Simple)1weaksent in clear
MD5 / HMAC-SHA2strongrecommended; key not in packet
Cryptographic (SHA-256+)2+strongestnewer IOS/XE

Config levels

! Per interface

! Per area (all interfaces in the area)
router ospf 1
 area 0 authentication message-digest

v2 vs v3 auth (exam favorite)

VersionNative authReal protection
OSPFv2MD5/SHA in headeryes (in-band)
OSPFv3noneIPv6 AH / ESP / IPsec
Trap: auth mismatch → neighbor stuck in INIT (hellos dropped), never reaches 2-Way. Key rotation uses key ID + sequence number — add the new key first, keep both briefly.

🧮 OSPF Summarization

OSPF summarizes only at boundaries: the ABR aggregates inter-area routes (area X range), the ASBR aggregates external routes (summary-address). OSPF cannot summarize inside an area — intra-area LSAs are always exact.

Where to summarize (memorize)

LocationCommandAggregates
ABRarea X range <net> <mask>inter-area routes (Type 3)
ASBRsummary-address <net> <mask>external redistributed (Type 5/7)
Inside an areanot possibleintra-area must be exact

Config

! ABR: inter-area summarization
router ospf 1
 area 1 range 10.1.0.0 255.255.0.0
 area 1 range 10.1.0.0 255.255.0.0 not-advertise   ! filter/suppress

! ASBR: external summarization
router ospf 1
 summary-address 10.2.0.0 255.255.0.0
 redistribute static subnets

Benefits

Smaller LSDB

fewer Type 3/5 LSAs

Less SPF CPU

shorter SPF runs

Stability

flaps contained at the boundary

Loop/black-hole note: the router advertising an aggregate needs to discard traffic to covered ranges it lacks (Null0 / discard-route) to avoid loops. And OSPF summarization ≠ auto-summarization.

🔧 OSPF Troubleshooting

Follow the layer model: interface → neighbor → LSDB → routes → forwarding. Most exam scenarios hang on neighbor-state issues (MTU, hello/dead, area, network type, auth) or area/type misconfiguration.

Must match

  • Hello / Dead timers
  • Area ID
  • Network type
  • Auth type + key

The top causes

  • MTU mismatch → ExStart
  • hello/dead → Down/Init
  • auth → Init
  • stub flag → no adjacency

The `show` progression

1 show ip interface brief — link up?
2 show ip ospf neighbor — adjacency?
3 show ip ospf database — LSDB sync?
4 show ip route ospf — SPF routes?
5 show ip cef / ping — forwarding?
MTU mismatch → stuck ExStart is the single most-tested OSPF fault. clear ip ospf process reconverges (brief outage) — a maintenance action, not a config fix.
