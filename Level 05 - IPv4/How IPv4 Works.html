VLSM rules: 1) Allocate LARGEST first to reduce fragmentation. 2) Size = 2^h ≥ hosts + 2 (reserve network + broadcast). 3) Start at valid block boundaries (multiples of block size). 4) Never overlap (e.g., 10.10.0.32/27 inside 10.10.0.0/26 overlaps). 5) Requires a classless routing protocol — RIPv1 does NOT carry masks and cannot support VLSM.

Memorize: 224.0.0.1 = all hosts · .2 = all routers · .5 = OSPF · .6 = OSPF DR/BDR · .9 = RIPv2 · .10 = EIGRP · .22 = IGMPv3
IPv4 → Ethernet Multicast MAC
IPv4 multicast has 28 group bits; Ethernet maps only 23 bits to 01:00:5E:0x:xx:xx.
Bits lost: 28 − 23 = 5 → 2⁵ = 32 IPv4 multicast groups map to the SAME Ethernet MAC. This many-to-one collision is normal and expected.
Exam trap: The switch can distinguish MACs but the MAC mapping can't uniquely identify every IPv4 multicast group.
IGMP vs PIM vs IGMP Snooping
IGMP: host↔router membership ("who wants group X?") — Layer 3
PIM: router↔router multicast routing — PIM-DM (flood→prune), PIM-SM (uses RP), PIM-SSM ((S,G), no RP)
IGMP snooping: Layer-2 switch feature that limits multicast flooding to ports with interested receivers

Note: Link-local multicast 224.0.0.0/24 is NOT forwarded by routers (this is why OSPF hellos stay local).
Broadcast key points: Directed broadcast = host bits all 1 for a subnet (e.g., 192.168.10.255). Limited broadcast = 255.255.255.255 (local only, never routed). Routers are broadcast boundaries. RIPv1 uses broadcast 255.255.255.255; RIPv2 uses multicast 224.0.0.9. IPv6 doesn't use ARP/broadcast — it uses Neighbor Discovery.
