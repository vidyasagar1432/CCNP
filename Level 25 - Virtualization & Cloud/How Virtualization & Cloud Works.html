Three layers: server virtualization (VMs & hypervisors, containers & orchestration), network virtualization (VRF — the routing-table slice, cloud VPCs), and cloud models & services (public/private/hybrid × IaaS/PaaS/SaaS).

🖥️ Server Virtualization — VM & Hypervisor

A VM = full guest OS on virtualized hardware (vCPU/vRAM/vNIC/vDisk) atop a hypervisor. The hypervisor schedules and isolates workloads.

🐳 Containers — Docker & Kubernetes

Containers package an app + dependencies, isolated via namespaces, limited via cgroups, sharing the host kernel. Docker = the runtime; Kubernetes = the orchestrator.

Container basics

Namespaces

isolation

cgroups

limit resources

Image → Container

app + deps

CNI (container network interface) is the plugin standard that connects containers to networks.

Docker object model

Dockerfile: FROM → base, RUN → build, COPY → files, EXPOSE → port, CMD → runtime command. Default network = bridge/NAT.

Kubernetes objects

Docker = runtime; K8s = orchestration. Pods run apps, Services expose them (stable VIP), Deployments maintain count. Control plane decides; workers run.

🕸️ Network Virtualization — VRF & VRF-Lite

VRF = multiple isolated routing tables on one router (own RIB, CEF/FIB, interfaces, protocol process). VRF-lite = the same isolation without MPLS/MP-BGP.

🧩 Cloud Service Models — IaaS · PaaS · SaaS
