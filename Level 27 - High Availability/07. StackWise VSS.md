# StackWise / VSS

> **Level 27 · High Availability** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**StackWise** and **VSS (Virtual Switching System)** make multiple physical switches behave
as **one logical switch**. **StackWise** links stackable Catalyst switches (e.g. 3750/3850)
into a single management entity with an **active/standby supervisor**; **VSS** virtualizes
two Catalyst 6500/4500 chassis into one logical switch with a **dual-active protection**
(VSL). The exam tests the logical-switch concept, the roles, and the distinguishing cable.

---

## 2. Core Concepts

### 2.1 What stacking achieves

| Benefit | Detail |
|---------|--------|
| One logical switch | single control plane/management |
| Shared config | one running-config |
| Port density | more ports under one STP domain |
| Failover | member/supervisor redundancy |
| EtherChannel | can span members (no STP block) |

- A stack/VSS is managed as **one device** — one loop-free L2 domain.

### 2.2 StackWise

| Item | Detail |
|------|--------|
| Members | stackable switches (3750/3850 series) |
| Cable | **StackWise** proprietary stacking cable |
| Roles | **active** (master), **standby**, member |
| Control | active holds control plane |
| Failover | standby takes over (SSO-style) |
| Management | one IP, one config |

- StackWise elects an **active (master)** and **standby**; the rest are stack members.

### 2.3 VSS

| Item | Detail |
|------|--------|
| Chassis | 2x Catalyst 6500/4500 |
| Link | **VSL (Virtual Switch Link)** — 40/10 G |
| Roles | **active** and **standby** virtual switch |
| Logical | one switch, one management |
| VSSP | treats both as one for STP |
| MEC | multichassis EtherChannel |

- VSS uses the **VSL** to sync and to detect failures between the two chassis.

### 2.4 Dual-active handling

| Mechanism | Detail |
|-----------|--------|
| Problem | both halves think they are active |
| Detect | PAgP/VSSP or BFD on links |
| Action | one side shuts down switching |
| Result | avoids split-brain |

- **Dual-active detection** prevents both chassis from running as active in a VSS.

### 2.5 StackWise vs VSS

| Aspect | StackWise | VSS |
|--------|-----------|-----|
| Platform | stackable switches | 6500/4500 chassis |
| Link | StackWise cable | VSL |
| Scale | up to 8-9 members | 2 chassis |
| Roles | active/standby/member | active/standby |
| Failover | standby takeover | SSO switchover |
| EtherChannel | across members | MEC across chassis |

## 5. Exam Traps

- **StackWise parses `show switch`; VSS parses `show vss`** — different platforms.
- StackWise uses a **StackWise cable**; VSS uses **VSL**.
- Both create **one logical switch** and allow **EtherChannel across members** (no STP block).
- StackWise: **active/standby/member**; VSS: **active/standby virtual switch**.
- **Dual-active detection** (VSSP/PAgP or BFD) prevents split-brain in VSS.

## 7. One-Minute Mental Model

**StackWise** and **VSS** are two flavors of "many boxes, one brain": StackWise ties
stackable switches with a **StackWise cable** into an **active/standby/member** fabric
(`show switch`), while **VSS** fuses two 6500/4500 chassis over a **VSL** into one logical
switch (`show vss`) with **dual-active detection** so they can't split into two active
halves. In both, EtherChannel can stretch across members, so STP stops blocking and
redundant uplinks stay fully active.
