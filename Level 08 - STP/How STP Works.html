🕸️ STP — Layer 2 loop prevention

STP (IEEE 802.1D) builds a loop-free logical topology over physically redundant Layer 2. It elects a Root Bridge, selects Root Ports and Designated Ports, and puts unnecessary paths into a non-forwarding state. Preventing loops prevents catastrophic failures.

Standard

802.1D
classic / slow convergence

Purpose

loop control
not a link-redundancy protocol

Replacement

802.1w
RSTP — rapid

Why L2 loops are catastrophic

ProblemWhat happens
Broadcast stormBroadcast / flooded frames circulate repeatedly
MAC-table flappingSwitch learns the same source MAC from different ports
Duplicate framesSame frame reaches the destination via multiple paths
CPU / link saturationContinuous flooding consumes bandwidth and switch CPU
Trap: Ethernet frames have no Layer-2 TTL/hop limit. So a loop lets frames circulate endlessly — no decrementing hop count to stop them.

STP decision process

1. Elect the Root Bridge (lowest Bridge ID)
2. Select a Root Port on each non-root switch
3. Select a Designated Port on each segment
4. Block redundant (non-designated) paths
Mental model: physical redundancy exists → STP computes which links may forward → some forward, some do not. That partial forwarding = a loop-free tree. STP does not remove the physical redundancy.

👑 Root Bridge election

The Root Bridge is the reference point of a spanning-tree instance. Every non-root switch computes its best path toward the root, and STP uses that to assign port roles. There is one root per spanning-tree instance.

Election rule

1. Lowest Bridge Priority
2. If tied → lowest Extended System ID / VLAN ID
3. If still tied → lowest MAC address
Simplified: lowest priority wins; if tied, lowest MAC wins.

🎭 Port Roles — responsibility, not state

A port role describes what a port does in the topology (its responsibility). A port state describes its current behavior. Role ≠ State.

Roles at a glance

Root Port (RP)
Best path from a non-root switch toward the Root. Normally Forwarding. (One per non-root switch per instance.)
Designated Port (DP)
Best port on a segment toward the Root. Normally Forwarding. One per segment.
Alternate Port
RSTP: backup path to the root (via another switch). Discarding until needed.
Backup Port
RSTP: backup for another DP on the same segment. Discarding.
Root: no Root Port — its active ports are normally Designated Ports.

🚦 Port States — blocking → forwarding

States describe a port's current forwarding/learning behavior. Classic 802.1D has 5 states; RSTP collapses these into 3.

Classic 802.1D states

StateForwards dataLearns MACPurpose
BlockingNoNoPrevents loops while receiving STP info
ListeningNoNoParticipates in STP calculation
LearningNoYesBuilds MAC-address table
ForwardingYesYesNormal data forwarding
DisabledNoNoAdministratively down / not participating

RSTP states

Discarding
no data · no learning
Learning
no data · learns MAC
Forwarding
data + learning
Key: RSTP merges Blocking + Listening into a single Discarding state, so 802.1D's 5 states become 3.

Blocking still participates

Important: A blocking/non-designated port can still receive BPDUs and continue monitoring STP information so it can react if the topology changes. Blocking is not "off."
Trap: Blocking does not forward user traffic, but it remains STP-aware and can transition to another state.

📨 BPDU — STP's control message

BPDU (Bridge Protocol Data Unit) is the control-plane message switches exchange to build and maintain the spanning tree.

What a Configuration BPDU carries

Root Bridge ID

who the root is

Root Path Cost

cost toward the root

Sender Bridge ID

who sent it

Sender Port ID

which local port

Timers

hello / max age / forward delay

TC / TCA flags

topology-change signaling
Hidden note: RSTP BPDUs (802.1w) also carry port role and proposal/agreement (P/A) information — that's how RSTP converges so fast.

How BPDUs move

1. Root emits Configuration BPDUs from its Designated Ports
2. Each non-root switch receives the best root info
3. It selects its Root Port
4. It transmits updated BPDUs from its Designated Ports
Trap: Do not think of STP as "root sends one BPDU, every switch blindly relays it unchanged." Each bridge evaluates received info, selects its own roles, and sends its own BPDUs from its Designated Ports.

BPDU comparison order

When comparing received STP information, evaluate fields in this order:

1. Lowest Root Bridge ID
2. Lowest Root Path Cost
3. Lowest Sender Bridge ID
4. Lowest Sender Port ID

TCN vs TC

TermMeaning
TCNTopology Change Notification — the mechanism used to notify the root of a topology change
TCTopology Change indication — a flag in Configuration BPDUs after a change
Trap: TCN ≠ TC. The TC indication (set by the root) causes temporary faster MAC aging — normally using Forward Delay (15 s) — so stale MAC entries are removed faster after a change.

⚡ RSTP (802.1w) — rapid convergence

RSTP (IEEE 802.1w) is the rapid evolution of STP. It converges in seconds instead of ~50 s because it stops relying on slow timers.

Why RSTP is faster

1. Explicit port roles (Root / Designated / Alternate / Backup)
2. Rapid transitions instead of timer-driven Listening/Learning
3. Proposal/Agreement sync handshake
4. Assumes point-to-point links for rapid behavior
5. Edge ports transition immediately
Proposal/Agreement: a Designated Port proposes; downstream switches agree; ports converge almost immediately rather than waiting out Forward Delay on every hop.

Classic STP vs RSTP

FeatureClassic STPRSTP
Standard802.1D802.1w
ConvergenceSlow (timers, ~50 s worst case)Rapid (P/A + roles)
StatesBlocking, Listening, Learning, ForwardingDiscarding, Learning, Forwarding
RolesRoot, Designated, Non-designatedRoot, Designated, Alternate, Backup
TransitionTimer-drivenProposal/Agreement + edge ports

🌿 PVST+ — one 802.1D instance per VLAN

PVST+ (Per-VLAN Spanning Tree) runs a separate spanning-tree instance per VLAN. Each VLAN gets its own root, its own Root/Designated/Blocking ports, and its own L2 forwarding behavior.

Modern Cisco defaults to Rapid PVST+ (RSTP per VLAN), not classic PVST+.

The big benefit: per-VLAN load balancing

Key idea: Because each VLAN has its own topology, the same physical interface can forward VLAN 10 while blocking VLAN 20 — enabling Layer-2 load balancing across parallel links.

🚀 Rapid PVST+ — RSTP per VLAN

Rapid PVST+ combines RSTP mechanics with per-VLAN instances. It gives you the fast convergence of 802.1w and the per-VLAN load balancing of PVST+.

Configuration

spanning-tree mode rapid-pvst

spanning-tree vlan 20 root secondary

spanning-tree vlan 10 priority 4096

show spanning-tree vlan 10
show spanning-tree summary

Per-VLAN root assignment

Each VLAN runs its own instance → each VLAN can have its own root:

VLAN 10

Root = SW1
one L2 path preferred

VLAN 20

Root = SW2
different L2 path preferred
Exam rule: Rapid PVST+ = RSTP mechanics + one instance per VLAN + root per VLAN. This is the default STP mode on modern Cisco switches.
Note: As the number of VLANs grows, per-VLAN instances consume more CPU/BPDU overhead — that's one reason large designs may prefer MST.

🗺️ MST (802.1s) — map many VLANs to few instances

MST (Multiple Spanning Tree) groups many VLANs into a smaller set of MST instances (MSTIs), reducing the number of spanning-tree instances the switch must run.

How MST groups VLANs

Root per MSTI, not per VLAN: In MST the root is elected per MST instance. All VLANs mapped to the same MSTI share that instance's topology.

MSTI 1

VLANs 10–20
Root = SW1

MSTI 2

VLANs 30–40
Root = SW2

VLAN 10, 11, 12 … 20 all map to MSTI 1 and share one topology. VLANs 30–40 share MSTI 2's topology.

MST region

Switches belong to the same MST region only when all of these match:

1. Same region name
2. Same revision number
3. Same VLAN-to-instance mapping
Trap: If any of those three differs, the switches are in different MST regions — even if only the mapping is off. Regions can still connect, but they run instances separately across the region boundary.

🛡️ STP protections — PortFast & Guards

These features harden STP edges and guard against misbehaving or malicious switches. They are not panaceas — each protects one specific failure mode.

PortFast

⚡ PortFast edge port

An edge-port feature: the port transitions to Forwarding immediately (skips Listening/Learning), because it expects an end host, not another switch. It does not disable STP.

interface GigabitEthernet0/1
spanning-tree portfast
Trap: PortFast + another switch on the link = a loop can form. That's why it's normally paired with BPDU Guard. In RSTP, a PortFast port is an edge port.

BPDU Guard

🚧 BPDU Guard err-disable

Protects edge / PortFast ports. If a BPDU arrives, the interface is placed into err-disabled state — because a real switch showed up where a host was expected.

interface GigabitEthernet0/1
spanning-tree bpduguard enable

Root Guard

👑 Root Guard root-inconsistent

Protects the intended root placement. If a superior BPDU (a would-be better root) arrives on the port, it goes root-inconsistent — it stops forwarding instead of letting the downstream switch hijack the root election.

interface GigabitEthernet0/24
spanning-tree guard root

Loop Guard

🔁 Loop Guard loop-inconsistent

Protects non-designated ports against unexpected BPDU loss. If BPDUs stop arriving (e.g. a unidirectional link), a non-designated port would otherwise start forwarding → potential loop. Loop Guard puts it into loop-inconsistent (discarding) until valid BPDUs resume.

interface GigabitEthernet0/2
spanning-tree guard loop

Which guard for which problem?

FeatureSignalsResult
PortFast—Immediate Forwarding (edge)
BPDU GuardBPDU received on edge porterr-disabled
Root GuardSuperior BPDU (new root threat)root-inconsistent (stops forwarding)
Loop GuardBPDUs stop arriving on non-designated portloop-inconsistent (discarding)
Distinction: BPDU Guard reacts to a BPDU being present; Loop Guard reacts to BPDUs being absent (and protects against the symptom, not the physical link failure itself).

🔗 EtherChannel — bundle links into one logical link

EtherChannel bundles multiple physical links into a single logical link. STP sees the bundle as one logical link, which removes the loop the individual physical links would create.
