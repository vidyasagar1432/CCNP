# Remote Access VPN (client-based)

> **Level 18 · VPN Technologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**Remote Access (RA) VPN** lets individual **users/clients** securely connect into the
enterprise over the Internet from any location. **Client-based** RA uses a software client
(typically Cisco **AnyConnect**) to build an encrypted tunnel; it gives users full network
access (full-tunnel) and corporate control, unlike clientless SSL. The exam tests
client-based **IPsec** and **SSL/AnyConnect** transport, split vs full tunneling, and
authentication/MFA.

---

## 2. Core Concepts

### 2.1 Client-based vs clientless

| Aspect | Client-based | Clientless (portal) |
|--------|--------------|---------------------|
| Client | software (AnyConnect) | browser only |
| Access | full network (full-tunnel) | apps in portal |
| Control | strong (DNS, ACL, policies) | app-level |
| Install | required | zero install |
| Transport | IPsec or SSL/DTLS | HTTPS |

- **Client-based = full-reach + control**; clientless = quick app access.

### 2.2 Two client-based transports

| Transport | Details |
|-----------|---------|
| **IPsec RA** | IPsec client (IKEv1/v2), UDP 500/4500, strong control |
| **SSL/AnyConnect** | TLS TCP 443, DTLS UDP 443, firewall-friendly |

- **IPsec RA** uses IKE (UDP 500/4500); **AnyConnect** rides **TLS/DTLS over 443**.

### 2.3 Full-tunnel vs split-tunnel

| Mode | Behavior | Use |
|------|----------|-----|
| Full-tunnel | all client traffic toward corporate | security/filtering |
| Split-tunnel | only corporate subnets; local Internet direct | performance |

- **Full-tunnel** forces all traffic through the ASA/headend (more control, more load).

### 2.4 Authentication, MFA, posture

| Layer | Mechanism |
|-------|-----------|
| User | AAA (RADIUS/LDAP) |
| MFA | tokens, Duo, cert, SMS |
| Posture | AnyConnect endpoint assessment |
| Group policy | per-user access, split/full, ACLs |
| Authorization | attributes from AAA |

- Modern RA = **MFA + certificate + posture** as the security triad.

### 2.5 AnyConnect details

| Item | Detail |
|------|--------|
| Client | Cisco AnyConnect |
| Headend | ASA / ASAv / ISR / FTD |
| Transport | TLS 443 (primary), DTLS 443 (optimal) |
| DTLS | UDP for real-time/latency-sensitive app |
| DPD | dead peer detection |
| Profiles | connect + group-policy |

- **DTLS (UDP 443)** gives lower latency than TLS for real-time apps.

### 2.6 Configuration command set (ASA headend)

```text
! IPsec RA (IKEv2)
crypto ikev2 enable outside
group-policy RA internal
 group-policy RA attributes
  vpn-tunnel-protocol ikev2 ssl-client
  split-tunnel-policy tunnelspecified
  split-tunnel-network-list value SPLIT-ACL
!
username user password cisco123
tunnel-group RA type remote-access
tunnel-group RA general-attributes
 address-pool POOL
 default-group-policy RA
```

| Command | Purpose |
|---------|---------|
| `crypto ikev2 enable` | enable IKEv2 on interface |
| `vpn-tunnel-protocol` | IPsec/SSL client allowed |
| `split-tunnel-policy` | full vs split |
| `tunnel-group ... remote-access` | RA tunnel group |

## 4. Troubleshooting & common failures

| Symptom | Likely cause | Check |
|---------|--------------|-------|
| Client can't connect | 443/500 blocked | transport |
| Auth loop | AAA/LDAP | vpn-sessiondb |
| No full access | split-tunnel policy | group-policy |

## 5. Exam Traps

- Client-based RA = software client (**AnyConnect**), **full network access**; clientless = browser.
- **IPsec RA = UDP 500/4500**; **SSL/AnyConnect = TCP 443 / UDP 443 (DTLS)**.
- **DTLS (UDP 443)** is the low-latency path for voice/video.
- **Full-tunnel = all traffic via headend**; split-tunnel = corporate only.
- RA security = **MFA + cert + posture + group policies**.

## 7. One-Minute Mental Model

**Client-based Remote Access VPN** = a per-user encrypted tunnel built by a software client
(AnyConnect) — either **IPsec (UDP 500/4500)** or **SSL (TLS 443 / DTLS 443)** — to a
headend (ASA/ISR). Pick **full-tunnel** for security/control, **split-tunnel** for
performance; secure it with **MFA, certificates, and posture**, all under a **group
policy**. It's the same reachability idea as SSL VPN (note 05) but with a client and full
network access instead of a browser portal.
