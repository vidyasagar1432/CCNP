# IPsec IKEv2 (IKEv2 vs IKEv1)

> **Level 18 · VPN Technologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**[[IKEv2]]** is the modern key-exchange protocol for IPsec, replacing the two-phase **IKEv1**
as the standard defined in RFC 7296. It merges IKEv1's phase 1 and phase 2 into a single
**IKE_INIT / IKE_AUTH** exchange pair, adds **built-in NAT-T** and **EAP** support, and is the
basis of **FlexVPN** and most modern IOS XE deployments. The exam tests the exchange flow
and the IKEv1 vs IKEv2 differences.

---

## 2. Core Concepts

### 2.1 IKEv1 vs IKEv2 — the big table

| Aspect | IKEv1 | IKEv2 |
|--------|-------|-------|
| Exchanges | phase 1 + phase 2 (4-6 msgs) | single IKE_SA (4 messages) |
| Phase 1 modes | main / aggressive | none (fixed INIT/AUTH) |
| SA negotiation | complex (multiple proposals) | streamlined |
| NAT-T | add-on (RFC 3948) | built-in/native |
| Authentication | PSK / RSA / cert | PSK / RSA / EAP |
| EAP (remote access) | not native | native |
| Rekey | separate IPsec SA phase | CREATE_CHILD_SA |
| Integrity | negotiated per transform | implicit in AUTH/encryption |
| State | more complex | simpler, more robust |
| Status | legacy | **preferred** |

### 2.2 The IKEv2 exchange flow

```
1. IKE_SA_INIT  (IKE_SA_INIT request/response)  -> DH + nonces -> IKE SA
2. IKE_AUTH     (IKE_AUTH request/response)     -> authenticate + build first child SA
3. CREATE_CHILD_SA  -> optional extra/later SAs and rekeying
4. INFORMATIONAL     -> delete, error, liveness
```

- The first **two message pairs** complete what IKEv1 needed four-to-six messages for.
- **IKE_SA_INIT** negotiates the DH, ciphers, and IKE SA integrity; **IKE_AUTH**
  authenticates the peer (with EAP if used) and creates the **first IPsec child SA**.

### 2.3 IKEv2 protocol details

| Item | Detail |
|------|--------|
| Standard | RFC 7296 (replaces 2407/2408/2409) |
| Ports | UDP 500 (IKE), UDP 4500 (NAT-T / ESP-in-UDP) |
| IKE SA lifetime | default 86400 s (24 h) default on Cisco |
| Child SA lifetime | 3600 s (1 h) default on Cisco |
| NAT discovery | NAT_DETECTION_SOURCE_IP / DESTINATION_IP payloads |
| Liveness | DPD (dead peer detection) |
| MTU | IKE packets can fragment |

### 2.4 IKEv2 building blocks on IOS XE

| Block | Role |
|-------|------|
| `crypto ikev2 proposal` | encryption + integrity + DH group |
| `crypto ikev2 policy` | proposal set + lifetime |
| `crypto ikev2 keyring` | pre-shared keys per peer |
| `crypto ikev2 profile` | match identity + authentication + keyring |
| `crypto ipsec transform-set` | IPsec data-plane algorithms |
| `crypto ipsec profile` | transform + `set ikev2-profile` |

- IKEv2 on IOS XE is configured with **profiles**, not the legacy `crypto isakmp` /
  `crypto map` scheme.

### 2.5 IKEv2 and remote access

- IKEv2 natively supports **EAP** (EAP-MSCHAPv2, EAP-GTC) for remote-access clients —
  the same IKEv2 profile terminates AnyConnect-style sessions.
- Certificate or **EAP authentication** replaces the weaker aggressive-mode PSK of IKEv1.

### 2.6 Configuration example (IKEv2 site-to-site)

```text
crypto ikev2 proposal PROP
 encryption aes-gcm-256
 integrity sha256
 group 14
!
crypto ikev2 policy POL
 proposal PROP
!
crypto ikev2 keyring KR
 peer SPOKE
  address 203.0.113.1
  pre-shared-key local Secret123
!
crypto ikev2 profile IKEV2-PROF
 match identity remote address 203.0.113.1
 authentication remote pre-share
 authentication local pre-share
 keyring local KR
!
crypto ipsec transform-set TS esp-aes-gcm
!
crypto ipsec profile IPSEC-PROF
 set transform-set TS
 set ikev2-profile IKEV2-PROF
```

## 4. Troubleshooting & common failures

|---------|--------------|-------|
| No IKE SA | proposal/policy mismatch | show crypto ikev2 sa |
| IKE_AUTH fails | keyring / match identity | show crypto ikev2 profile |
| Authentication error | PSK/cert mismatch | keyring |
| No child SA | transform set | show crypto ipsec sa |
| DPD drops | no liveness / NAT | show crypto session |
| NAT issue | no NAT-T | port 4500 |

## 5. Exam Traps

- IKEv2 combines phases into **one IKE_SA with IKE_INIT + IKE_AUTH** — not main/aggressive modes.
- **IKEv2 is the modern standard (RFC 7296); IKEv1 is legacy.**
- IKEv2 **natively supports EAP and NAT-T**; IKEv1 needs add-ons.
- Ports stay **UDP 500 / 4500** (NAT-T) for both versions.
- On IOS XE, IKEv2 uses **profiles** (proposal/policy/keyring/profile), not legacy `crypto map`.

## 7. One-Minute Mental Model

**IKEv2** is IPsec key management without IKEv1's complexity: one IKE_SA (4 messages) does
what IKEv1 needed two phases for, plus built-in NAT-T and EAP. On IOS XE you configure it
with **proposals → policy → keyring → profile** — the exact machinery FlexVPN reuses. If
you see main/aggressive mode or `crypto isakmp`, it's IKEv1 (legacy); `crypto ikev2` +
`IKE_INIT/IKE_AUTH` is the modern, preferred path.
