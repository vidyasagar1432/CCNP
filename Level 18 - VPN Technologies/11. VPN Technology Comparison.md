# VPN Technology Comparison

> **Level 18 · VPN Technologies** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

ENCOR expects you to **choose the right VPN technology** for a given topology: **GRE**
(transport + multicast), **IPsec** (encryption), **DMVPN** (dynamic spokes over Internet),
**FlexVPN** (unified IKEv2 framework), **GET VPN** (tunnel-free any-to-any over
MPLS/backbone), and **SSL** (remote user access). This note consolidates the trade-offs so
you can pick correctly under exam pressure.

---

## 2. Core Concepts

### 2.1 The six technologies at a glance

| Tech | Building blocks | Best for | Encryption |
|------|-----------------|----------|------------|
| **GRE** | IP proto 47 tunnel | transport, multicast, routing | none (add IPsec) |
| **IPsec** | ESP/AH + IKE | point-to-point confidentiality | yes |
| **DMVPN** | mGRE + NHRP + IPsec | dynamic hub/spoke over Internet | yes |
| **FlexVPN** | IKEv2 profiles | unified S2S/RA/hub-spoke | yes |
| **GET VPN** | GDOI group key | tunnel-free any-to-any on MPLS | yes |
| **SSL VPN** | TLS/DTLS 443 | remote user / clientless | yes |

### 2.2 GRE vs IPsec

| Aspect | GRE | IPsec |
|--------|-----|-------|
| Encryption | none | yes |
| Multicast | yes | not directly |
| Routing over it | yes (any IGP/BGP) | via VTI/GRE |
| Header overhead | 4 B + 20 B outer | ESP (varies) |
| Typical combination | GRE-in-IPsec | site-to-site |

### 2.3 DMVPN vs FlexVPN

| Aspect | DMVPN | FlexVPN |
|--------|-------|---------|
| IKE | IKEv1 or v2 | IKEv2 only |
| Key tech | NHRP + mGRE | IKEv2 profiles |
| Modes | dynamic spoke-spoke | S2S + RA + hub-spoke |
| Config | NHRP + multipoint | profile-driven |
| Spoke discovery | NHRP (NHS) | NHRP or profile |

### 2.4 GET VPN vs DMVPN vs crypto map

| Aspect | GET VPN | DMVPN | Crypto map / VTI |
|--------|---------|-------|------------------|
| Tunnel if | none | mGRE | VTI/GRE |
| Data path | direct any-to-any | spoke-spoke (ph2) | point-to-point |
| Key | GDOI group key | per-tunnel IKE | per-tunnel IKE |
| Overlay | no (native) | NHRP | IGP over tunnel |
| Best | MPLS backbone | Internet branches | fixed sites |

### 2.5 SSL vs IPsec remote access

| Aspect | SSL VPN | IPsec RA |
|--------|---------|----------|
| Client | browser/AnyConnect | IPsec client |
| Ports | 443 (TLS/DTLS) | 500/4500 |
| NAT/firewall friendly | yes | sometimes blocked |
| Control | moderate | strong |
| Setup friction | low | higher |

### 2.6 Choosing the right technology (decision table)

| Requirement | Choice |
|-------------|--------|
| Encryption between two fixed sites | IPsec (or GRE over IPsec) |
| Carry multicast + routing protocols | GRE over IPsec |
| Dynamic branches over Internet, no hub bottleneck | DMVPN |
| One framework for site-to-site + remote access | FlexVPN |
| Any-to-any encryption over MPLS without tunnels | GET VPN |
| Remote users from anywhere, minimal client friction | SSL VPN |

## 4. Exam Traps

- **GRE alone does NOT encrypt** — pair with IPsec.
- **DMVPN = mGRE + NHRP + IPsec**; FlexVPN = IKEv2 profiles.
- **GET VPN has no tunnels** — GDOI group key, best on MPLS/backbone.
- **SSL VPN (443) is firewall-friendly**; IPsec RA uses 500/4500.
- Choose by **topology + traffic**: dynamic spokes → DMVPN/FlexVPN; users → SSL; MPLS any-to-any → GET.

## 6. One-Minute Mental Model

Think of VPN choice by **who travels and over what**: two fixed sites → **IPsec/GRE**; many
roaming branches over the Internet → **DMVPN** (NHRP) or **FlexVPN** (IKEv2 profiles); a
private backbone where you want native any-to-any with no tunnels → **GET VPN** (GDOI group
key); individual remote users → **SSL/AnyConnect** on 443. GRE is the transport glue;
IPsec is the encryption — and when in doubt, map the topology to the single word that
defines each technology.
