GRE ≠ encryption. GRE alone is not secure — pair it with IPsec. That's the classic site-to-site recipe.

🧸 GRE — Generic Routing Encapsulation

A virtual L3 tunnel interface that carries any L3 payload (IPv4, IPv6, multicast). No encryption, no reliability — usually wrapped with IPsec.

It carries multicast + routing

Because GRE is a normal virtual interface, OSPF / EIGRP / BGP and multicast run over it — IPsec alone cannot do this directly.

Trap: GRE is IP protocol 47 — NOT TCP/UDP. There's no GRE port number.

🔐 IPsec — protocols, modes, IKE

IPsec supplies the actual encryption/authentication. Two protocols: AH (51) and ESP (50).

AH vs ESP

AH — protocol 51

integrity + authentication only. Does NOT encrypt. No NAT traversal.

ESP — protocol 50

confidentiality + integrity + auth. The standard for real encryption. NAT-T wraps it in UDP 4500.

Interesting traffic (policy-based)

In classic (crypto map) IPsec, the ACL defines what the tunnel protects. Both sides must define mirror-image ACLs. Only matching traffic is encrypted. No interesting traffic = no IPsec SA, even if IKE is up — a top trap.

🕸️ DMVPN — Dynamic Multipoint VPN

Dynamic hub-and-spoke over the Internet. Three building blocks: mGRE + NHRP + IPsec.

The three building blocks (memorize)

mGRE

multipoint GRE

one tunnel interface, many destinations

NHRP

resolution

resolves spokes' public IPs; hub = NHS

IPsec

encrypt

protects the mGRE tunnel

Spoke-to-spoke shortcut

1 spokes NHRP-register with hub (NHS)
2 Spoke A wants B → NHRP resolution query to hub
3 hub replies "B is at X.X.X.X"
4 A builds direct IPsec GRE tunnel to B
5 data flows directly — no hub hair-pinning
Key idea: control stays at the hub; data goes directly between spokes (phase 2+).

DMVPN phases

Phase 1

hub-and-spoke only, no shortcuts

Phase 2

spoke-to-spoke shortcuts (default)

Phase 3

NHRP redirect / best-path routing

Trap: DMVPN = mGRE + NHRP + IPsec. NHRP resolves spoke public IPs via the hub (NHS). Data goes spoke-to-spoke (phase 2+).

🧩 FlexVPN — IKEv2 profile framework

Cisco's IKEv2-based unified VPN framework handling site-to-site, remote access, hub-and-spoke, and spoke-to-spoke with the same IKEv2 profile building blocks.

IKEv2 profile chain (memorize)

1 crypto ikev2 proposal (enc+int+DH)
2 crypto ikev2 policy (proposal+lifetime)
3 crypto ikev2 keyring (PSKs)
4 crypto ikev2 profile (match+auth+keyring)
5 crypto ipsec profile (transform+ikev2)
crypto ikev2 proposal FlexProp

crypto ipsec profile FlexIPsec
 set transform-set AES-SHA

interface Tunnel0
 tunnel protection ipsec profile FlexIPsec
FlexVPN vs DMVPN: DMVPN is NHRP + mGRE (hub-spoke focus, IKEv1 or v2). FlexVPN is IKEv2-native, profile-driven, and adds remote access mode — unified/simpler. FlexVPN can run hub-spoke using NHRP too.

🎯 GET VPN — tunnel-free any-to-any

Encrypts any-to-any over an MPLS/IP backbone without tunnel interfaces. All group routers share a common group key managed via GDOI.

GDOI model

Key Server (KS)

manages + distributes group keys

Member

group router that encrypts

GDOI

group key mgmt · UDP 848

TEK vs KEK (memorize)

TEK — Traffic Encryption Key

encrypts the actual data between members

KEK — Key Encryption Key

protects TEK distribution

How it works

1 member registers with KS (GDOI UDP 848)
2 KS sends KEK + TEK
3 member A encrypts directly to B with shared TEK
4 no tunnel built between them
Trap: GET VPN has no tunnel interfaces and no overlay routing — underlay routes natively. GDOI = UDP 848. COOP provides redundant key servers (HA).

🌍 SSL VPN + Remote Access

Lets individual users connect over the Internet. SSL VPN rides TCP 443 (TLS) — the big advantage is it gets through most firewalls/NAT.
