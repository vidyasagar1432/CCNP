What is Route Redistribution?

Route redistribution injects routes from one routing protocol domain into another at a boundary router (ASBR / redistribution point). Enterprises must redistribute when a network runs multiple protocols — the classic example is OSPF in the campus and EIGRP in the WAN, or either IGP feeding a provider over BGP.

Why redistribute
Routing protocols do not talk to each other natively. Redistribution is the bridge — but the metrics, AD values and route semantics do not translate. You must seed metrics, watch administrative distances, and filter to survive.
The three mechanical problems
1) Seed metrics — the receiving protocol needs a metric it understands.
2) Administrative distance — AD decides conflicts, and redistribution creates them.
3) Loops — two-way redistributing without filters feeds routes back into themselves.

Exam trap: redistribution is not symmetric by default. Configuring OSPF → EIGRP on one router gives you reachability in exactly one direction. The reverse direction needs its own `redistribute` command with its own seed metric.

Seed Metrics

Every redistributed route enters the receiving protocol with a seed metric. EIGRP is the dangerous one — no default exists.

What does each protocol expect?

EIGRPNoneRoutes not advertised — invisible
OSPFauto-cost / 20 externalE1/E2 with default cost
BGPMED = 0Provider prefers 0 — attractive!

Exam trap: EIGRP has no default seed metric. `redistribute ospf 1` without a metric or default-metric silently drops every route — this is the number-one redistribution exam point. OSPF and BGP always produce something; EIGRP produces nothing.

AD duel — who wins?

Pick two sources for the same prefix and see which one the RIB installs.

vs
TIE — {{ adVerdict.text }}
AD beats metric. Always. A redistributed route with an amazing metric still loses to any lower-AD source. EIGRP external (170) loses to OSPF (110) — the classic redistribution surprise.

The internal vs external trap

redistribute ospf 1 creates EIGRP external routes with AD 170. If the same prefix also exists as an EIGRP internal route (AD 90), the internal one wins and the redistributed copy is ignored entirely. Reverse direction: OSPF (110) beats an EIGRP-external copy. 

router ospf 1
 distance 120 10.0.0.1 0.0.0.0 ACL-OSPF-LOW   ! give the real source a lower AD
router eigrp CAMPUS
 address-family ipv4 unicast autonomous-system 100
  topology base
   distance eigrp 90 200                          ! internal / external separately

Priority order when designing redistribution: 1) existence (filtering) → 2) AD → 3) metric. Filter first, then align ADs deliberately instead of relying on defaults.

Route Tags

Tags label routes as they enter a protocol so downstream routers can identify origin and apply policy. Tags survive redistribution boundaries.

Tag fields per protocol

ProtocolTag field
OSPFExternal route tag (E1/E2 only, 32-bit)
EIGRPRoute tag (32-bit)
RIPRoute tag (16-bit)
BGPCommunity — the tag analog (ASN:value)
Exam trap: OSPF carries tags only on external routes (E1/E2). Internal OSPF routes have no tag field — if you need to mark internal routes, redistribute them or use another mechanism.

Downstream, match the tag to apply policy — or to deny the return path (the loop-prevention backbone, section 7):

route-map CATCH-TAG permit 10
 match tag 100
 set metric 10000 100 255 1 1500

Filtering

Filtering decides which routes cross the boundary. Blind redistribution creates loops, black holes and metric surprises.

Filter placement

FilterCommandDirection
Route-mapredistribute ospf 1 route-map RMat redistribution
Distribute-list (EIGRP)distribute-list ACL in/outper protocol
Distribute-list (OSPF)distribute-list ACL inOSPF in only
Prefix-list in route-mapmatch ip address prefix-list PLselection
Exam trap: OSPF distribute-lists on Cisco IOS are `in` only — there is no `distribute-list … out` for OSPF. The standard tool for redistribution filtering is the route-map attached to the `redistribute` command.

The route-map pattern (recommended)

ip prefix-list ALLOWED seq 10 permit 10.10.0.0/16 le 24
ip prefix-list ALLOWED seq 20 permit 192.168.0.0/24

route-map FILTER-REDIST permit 10
 match ip address prefix-list ALLOWED
 set metric 10000 100 255 1 1500

router eigrp CAMPUS
 address-family ipv4 unicast autonomous-system 100
  topology base
   redistribute ospf 1 route-map FILTER-REDIST
Prefix matches permit?route-map evaluates sequences in order
→
Yes → allowed + set actionsseed metric, tag, MED
→
No more sequencesimplicit deny at the end
→
Route droppednot redistributed
Implicit deny: a route-map ends with an implicit deny. Anything that matches no permit sequence is silently dropped at the boundary. This is a feature — use it to make your allow-list explicit.

Direction gotcha — local, not neighbor

Filter direction is measured on the local router:

  • redistribute ospf 1 route-map RM filters what enters EIGRP locally.
  • neighbor … route-map RM out (BGP) filters what leaves to a peer.

Misplaced direction = routes slip straight through your policy. Verify with show route-map counters.

Run your design through this flow before you write any config. It never lets a loop in.
Is there exactly one boundary router between the two domains?
YES↓
Cleanest design — no feedback pair, predictable metrics
↓
Are seed metrics set on both directions?
NO↓
Routes silently dropped (EIGRP) / MED 0 (BGP) — fix seeds first
YES↓
Functional — add tags + filters to harden
NO↓
Symmetric filters on BOTH boundary routers?
NO↓
LOOP RISK — stop. Add filters before anything else
YES↓
Routes tagged at entry, tag denied on return?
NO↓
Working but fragile — add tags for deterministic loop breaking

Quick review: worst practice = two-way blind redistribute. Best practice = tags at entry + deny on return + route-map filters + deliberate ADs.
