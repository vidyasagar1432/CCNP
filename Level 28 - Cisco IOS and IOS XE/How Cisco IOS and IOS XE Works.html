📟 Cisco IOS & IOS XE — the whole picture

Operate a device: CLI modes, licensing, and file/image management (upgrade, backup, recovery). Then the modern layer: IOS XE = modular daemons on Linux, YANG + RESTCONF/NETCONF, and device hardening.

The three blocks

Operate

CLI + modes

config modes, privilege 15

Manage

lic + files

licensing, upgrade, backup, recovery

Modern

IOS XE

daemons on Linux · YANG/RESTCONF · hardening

IOS XE = monolithic IOS re-architected as modular daemons (IOSd) on a Linux kernel — same CLI, SMU patches, model-driven management, streaming telemetry.

⌨️ The Command-Line Interface

EXEC commands (show, ping) run in privileged mode; configure commands (interface, router) run in config mode. Help (`?`), Tab completion, and `do` speed you up.

Mode picker

Config

`?` gives context help; `?` right after a word (no space) completes it. `do` runs an EXEC command from inside config mode. Ctrl+Z/end exits config. Privilege 15 = enable (full).

⬆️ Software Upgrade

Copy the new image to flash, set `boot system flash:`, verify, save, reload, verify version. The image is NOT run in-place — you must point boot at it.

The upgrade flow

1 check space
2 copy image
3 verify MD5
4 boot system
5 save + reload
6 show version
`boot system flash:` is REQUIRED — the image won't auto-boot. Keep the old image for rollback. SMU = targeted patch, not a full image.
copy tftp://10.0.0.5/ios-xe-new.bin bootflash:
verify /md5 bootflash:ios-xe-new.bin
boot system bootflash:ios-xe-new.bin
copy running-config startup-config
reload
show version
show boot

💾 Configuration Backup

Copy running/startup config off-box (TFTP/SCP/FTP/USB) or use the archive feature for automatic, versioned snapshots.

The archive pattern

`archive` + `path` + `write-memory` + `maximum N` auto-saves versions. `show archive` lists generation. `configure replace file:` applies an archived config.
`copy run start` is NOT off-box backup (NVRAM only) — go off-box for real DR.
archive
 path tftp://10.0.0.5/archive
 write-memory
 maximum 14
show archive
copy running-config tftp://10.0.0.5/r1-run.cfg
copy tftp://10.0.0.5/r1-run.cfg running-config
configure replace flash:config.bak

🧩 YANG & RESTCONF/NETCONF on IOS XE

YANG = data-modeling language (structured tree). NETCONF and RESTCONF = the model-driven protocols that read/write it. The native Cisco model mirrors the CLI.

Protocol picker (memorize)

NETCONF
SSH 830 · XML · RPC (RFC 6241)
RESTCONF
HTTPS 443 · JSON/XML · REST (RFC 8040)
{{ yangVerdict.text }}
YANG = the blueprint (model); NETCONF/RESTCONF = the delivery trucks (protocols). Enable: `restconf` and `netconf-yang`. Models: Cisco-IOS-XE-native (mirrors CLI) vs OpenConfig (multi-vendor).

 netconf-yang

end

🔒 Device-Level Security Hardening

Secure the management and control planes: AAA, CoPP, SSH (not Telnet), SNMPv3, least privilege.

AAA server picker (the core contrast)

TACACS+
TCP 49 · separates A/A/A · encrypts all 3
RADIUS
UDP 1812/1813 · combines · encrypts password only
{{ aaaVerdict.text }}
CoPP rate-limits control-plane traffic (`control-plane` + `service-policy input`); MPP restricts mgmt protocols to mgmt interfaces. `enable secret` is hashed (vs weak `enable password`). SSH not Telnet; SNMPv3.

aaa authentication login default group tacacs+ local
username admin privilege 15 secret StrongPass
enable secret HashedSecret
ip ssh version 2
line vty 0 4

 login local
no ip http server
snmp-server group MGT v3 priv
control-plane
 service-policy input COPP
