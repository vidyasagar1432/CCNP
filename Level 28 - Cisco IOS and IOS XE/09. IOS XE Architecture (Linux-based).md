# IOS XE Architecture (Linux-based / daemons)

> **Level 28 · Cisco IOS and IOS XE** — CCNP Enterprise (ENCOR 350-401)

---

## 1. Overview

**[[IOS XE]]** is IOS re-architected to run as **applications (daemons) on top of a Linux
kernel**, where a single **IOSd daemon** implements the classic [[Cisco IOS|IOS]] control plane inside a
**Controller** container. This modular design gives process isolation, **in-service patching
(SMU/EEM)**, sub-packaging, and cleaner software management (install mode). The exam tests
the daemon/controller model and how it differs from monolithic IOS.

---

## 2. Core Concepts

### 2.1 The fundamental split

| Component | Role |
|-----------|------|
| **Linux kernel** | hosts the platform |
| **IOSd daemon** | runs the classic IOS control plane |
| **Controller** | container/orchestration framework |
| **Manager / Protocols** | platform services, data plane |

- IOS XE = **Linux kernel + modular daemons**, with **IOSd** as the IOS process.

### 2.2 Key daemons / processes

| Process | Function |
|---------|----------|
| **IOSd** | routing/switching control plane |
| **fman** / **FMAN-FP** | features and forwarding managers |
| **Controller** | runs the system |
| **hman** | hardware state/device management |
| **Platform processes** | power, fan, line-card mgmt |

- The control plane lives mostly in **IOSd**; hardware is handled by platform daemons.

### 2.3 IOS XE vs classic IOS

| Aspect | Classic IOS | IOS XE |
|--------|-------------|--------|
| Architecture | monolithic | modular daemons on Linux |
| Process isolation | limited | strong |
| Package/upgrade | boot one image | subpackages / SMU |
| Patching | full reload | SMU without full reload |
| Management | CLI | + RESTCONF/NetConf, gNMI |
| Dynamic behavior | static | EEM, NBAR, streaming telemetry |

- **IOS XE supports streaming telemetry and model-driven mgmt** (note 10) that classic IOS lacks.

### 2.4 Subpackages and packaging

| Package | Meaning |
|---------|---------|
| **RPMs / subpackages** | individual components |
| **SMU** | Small Maintenance Upgrade (patch) |
| **FSU** | Feature Set Upgrade |
| **Composite image** | bundled install |
| **Software Add-ons** | optional feature packages |

- IOS XE install mode uses **SMUs (patches)** that do not require a full reload.

### 2.5 Config/persistence and reload behavior

| Behavior | Detail |
|----------|--------|
| CLI config | still Cisco CLI |
| Running config | in memory (Linux processes) |
| Startup | NVRAM |
| Non-volatile state | daemon-managed |
| Atomic reload | reboot of Linux + daemons |

- From the operator's view the CLI is identical, but behind it are **Linux processes**.

## 5. Exam Traps

- **IOS XE = modular daemons on a Linux kernel**, not a single monolithic image.
- **IOSd** is the daemon running the classic IOS control plane.
- SMU = **patch without full reload** (differs from classic IOS).
- IOS XE adds **model-driven management (RESTCONF/NetConf) and streaming telemetry**.
- For the operator, **CLI stays the same** — the architecture underneath changed.

## 7. One-Minute Mental Model

**IOS XE** = "IOS on Linux." The kernel hosts modular **daemons**, and the classic IOS
control plane is just one daemon — **IOSd** — running in a **Controller**. Because the
parts are isolated, you get **SMU patches** without a full reload, plus **model-driven
management and streaming telemetry** that monolithic IOS can't do. To the CLI operator
nothing looks different; the resilience and manageability underneath is what changed.
